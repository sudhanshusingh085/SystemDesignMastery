Machine Coding — Writing Code Under Pressure

💡 What to expect: The Machine Coding round requires you to produce working, well-designed code in a short time. This guide provides a battle-tested template and approach to conquer it.

1. What is Machine Coding?

Machine coding is an interview round (usually 60-90 minutes) where you are given a problem statement and must write working, executable code that solves it using Object-Oriented Principles.

📖 Machine Coding vs LLD: While LLD (Low-Level Design) focuses on class diagrams, APIs, and theoretical design, Machine Coding requires actual implementation. The code must compile and run!

2. The Approach Template

Time management is the most critical skill. Follow this strict timeline for a 90-minute round:

flowchart LR A[0-5m: Understand & Ask] --> B[5-15m: Identify Entities] B --> C[15-25m: Interfaces & Enums] C --> D[25-60m: Core Logic] D --> E[60-70m: Edge Cases] E --> F[70-90m: Demo/Main & Test]

Figure 1: Recommended Machine Coding Timeline

  • 1
    0-5 min: Read & Clarify. Understand the core requirements. Ask about constraints (e.g., "Do we need a real DB or is in-memory fine?").
  • 2
    5-15 min: Identify Entities. Jot down the main nouns. These will be your classes/records.
  • 3
    15-25 min: Define Interfaces & Enums. Establish the contracts. Use enums for statuses, types, etc.
  • 25-60 min: Implement Core Logic. Build the services and repositories. Focus on the happy path first.
  • 60-70 min: Error Handling. Add custom exceptions and handle edge cases (e.g., duplicate entries, not found).
  • 70-90 min: Main Method. Write a compelling Main.java that demonstrates your code working. This is crucial!

3. Code Structure Template

Structure your Java code in logical packages (even if it's all in one file for an online IDE, use static nested classes to simulate structure):

com.example.system
├── model/       # Entities, Records, Enums
├── repository/  # Data access interfaces and in-memory impls
├── service/     # Business logic
├── strategy/    # Interchangeable algorithms (if needed)
├── exception/   # Custom exceptions
└── Main.java    # Demo application

4. Time Management Tips

  • Don't gold-plate: Get a working solution first, then refactor.
  • Focus on core: If it's a parking lot, focus on parking and unparking, not user authentication.
  • Use Enums early: They make your code robust and prevent invalid states.
  • In-Memory DB: Always use HashMap or ConcurrentHashMap for storage unless a real DB is explicitly required.

5. Common Mistakes

❌ Avoid These

  • Starting to code without a plan
  • Over-engineering (YAGNI violation)
  • Putting all logic in one massive class
  • Using hard-coded strings (use constants/enums)
  • Running out of time before writing a Main method to test

✅ Do These

  • Follow the timeline strict
  • Apply SOLID and DRY principles
  • Use meaningful variable names
  • Separate models, repositories, and services
  • Provide a working Demo

6. Evaluation Criteria

What do interviewers actually look for?

  1. Working Code > Perfect Code: A complete, working solution with average design beats a perfectly designed, half-finished application.
  2. OOP Usage: Correct use of interfaces, abstract classes, encapsulation.
  3. Design Patterns: Using Strategy, Factory, or Observer where it naturally fits (don't force them).
  4. Code Readability: Clean code, good naming, no magic numbers.
  5. Extensibility: Can a new feature be added easily?

7. Practice Problem Walkthrough: Task Management System

Let's design a simple Task Management System following our template.

Java 21 
import java.util.*;
import java.util.concurrent.ConcurrentHashMap;
import java.util.stream.Collectors;

// --- 1. Enums & Models (Using Java 21 Records) ---
enum Priority { LOW, MEDIUM, HIGH }
enum Status { TODO, IN_PROGRESS, DONE }

// Record for immutable ID
record TaskId(String id) {
    public TaskId() { this(UUID.randomUUID().toString()); }
}

// Entity Class
class Task {
    private final TaskId id;
    private String title;
    private Priority priority;
    private Status status;

    public Task(String title, Priority priority) {
        this.id = new TaskId();
        this.title = title;
        this.priority = priority;
        this.status = Status.TODO;
    }

    // Getters and Setters...
    public TaskId getId() { return id; }
    public Status getStatus() { return status; }
    public void setStatus(Status status) { this.status = status; }
    
    @Override
    public String toString() {
        return "Task[" + id.id().substring(0,5) + "] " + title + " (" + priority + ", " + status + ")";
    }
}

// --- 2. Exceptions ---
class TaskNotFoundException extends RuntimeException {
    public TaskNotFoundException(String message) { super(message); }
}

// --- 3. Repository (Data Layer) ---
interface TaskRepository {
    void save(Task task);
    Optional<Task> findById(TaskId id);
    List<Task> findAll();
}

class InMemoryTaskRepository implements TaskRepository {
    // ConcurrentHashMap for thread safety
    private final Map<TaskId, Task> storage = new ConcurrentHashMap<>();

    @Override
    public void save(Task task) { storage.put(task.getId(), task); }

    @Override
    public Optional<Task> findById(TaskId id) { return Optional.ofNullable(storage.get(id)); }

    @Override
    public List<Task> findAll() { return new ArrayList<>(storage.values()); }
}

// --- 4. Service (Business Logic) ---
class TaskService {
    private final TaskRepository repository;

    // Dependency Injection
    public TaskService(TaskRepository repository) {
        this.repository = repository;
    }

    public TaskId createTask(String title, Priority priority) {
        Task task = new Task(title, priority);
        repository.save(task);
        return task.getId();
    }

    public void updateStatus(TaskId id, Status newStatus) {
        Task task = repository.findById(id)
            .orElseThrow(() -> new TaskNotFoundException("Task " + id + " not found"));
        task.setStatus(newStatus);
        repository.save(task);
    }

    public List<Task> getTasksByStatus(Status status) {
        return repository.findAll().stream()
                .filter(t -> t.getStatus() == status)
                .collect(Collectors.toList());
    }
}

// --- 5. Main Demo ---
public class Main {
    public static void main(String[] args) {
        System.out.println("--- Task Management System Demo ---");
        
        // Setup
        TaskRepository repo = new InMemoryTaskRepository();
        TaskService service = new TaskService(repo);

        // Core flow execution
        TaskId task1 = service.createTask("Setup Database", Priority.HIGH);
        TaskId task2 = service.createTask("Write API Docs", Priority.MEDIUM);

        System.out.println("Created Tasks:");
        service.getTasksByStatus(Status.TODO).forEach(System.out::println);

        System.out.println("\nUpdating Task 1 to IN_PROGRESS...");
        service.updateStatus(task1, Status.IN_PROGRESS);

        System.out.println("\nTasks In Progress:");
        service.getTasksByStatus(Status.IN_PROGRESS).forEach(System.out::println);

        // Exception test
        try {
            service.updateStatus(new TaskId("invalid-id"), Status.DONE);
        } catch (TaskNotFoundException e) {
            System.out.println("\nExpected Error: " + e.getMessage());
        }
    }
}
