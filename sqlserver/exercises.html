Q1: Total Trade Volume and Volume Weighted Average Price (VWAP)
Easy

Write a query to calculate the total shares traded, total gross notional, and Volume Weighted Average Price (VWAP = SUM(Quantity * Price) / SUM(Quantity)) for each security on the current trade date.

💡 View Solution & Explanation ▼ 
SELECT 
    o.SecurityID,
    s.Ticker,
    SUM(CAST(e.FillQuantity AS BIGINT)) AS TotalSharesTraded,
    SUM(CAST(e.FillQuantity AS DECIMAL(18,4)) * e.FillPrice) AS TotalGrossNotional,
    CAST(SUM(CAST(e.FillQuantity AS DECIMAL(18,4)) * e.FillPrice) / 
         NULLIF(SUM(CAST(e.FillQuantity AS DECIMAL(18,4))), 0) AS DECIMAL(18,4)) AS VWAP
FROM Executions e
INNER JOIN Orders o ON e.OrderID = o.OrderID
INNER JOIN Securities s ON o.SecurityID = s.SecurityID
WHERE CAST(e.ExecutedAt AS DATE) = CAST(SYSUTCDATETIME() AS DATE)
GROUP BY o.SecurityID, s.Ticker;
Key Tip: CAST(... AS BIGINT) avoids overflow on large volumes, and NULLIF(..., 0) protects against divide-by-zero crashes.

Q10: Aggregating with HAVING vs WHERE Performance Filter
Easy

💡 View Solution & Explanation ▼ 
SELECT 
    AccountID,
    COUNT(OrderID) AS TotalBuyOrders
FROM Orders
WHERE OrderSide = 'BUY' 
  AND CAST(OrderTime AS DATE) = CAST(SYSUTCDATETIME() AS DATE) -- WHERE filters rows before grouping!

Q19: Anti-Join NULL Trap Demonstration with NOT IN
Medium

Demonstrate how WHERE Col NOT IN (SELECT NullableCol FROM Table) breaks completely when a NULL is present.

💡 View Solution & Explanation ▼ 
-- Why NOT IN fails:
-- (Value NOT IN (1, 2, NULL)) expands logically to:
-- (Value <> 1) AND (Value <> 2) AND (Value <> NULL)
-- Because (Value <> NULL) is UNKNOWN, the entire AND chain evaluates to UNKNOWN!
-- Result: 0 rows returned!
-- Fix: Always use NOT EXISTS!
3-valued logic trap: Any expression AND UNKNOWN evaluates to UNKNOWN or FALSE.

Q26: Gaps and Islands: Consecutive Win/Loss Settlement Streaks
Hard

Identify streaks of consecutive profitable trading days per account using ROW_NUMBER() - ROW_NUMBER().

💡 View Solution & Explanation ▼ 
WITH DailyPnL AS (
    SELECT AccountID, CAST(TransactionTimestamp AS DATE) AS TradeDate,
           IIF(SUM(Amount) > 0, 'PROFIT', 'LOSS') AS DayOutcome
    FROM LedgerTransactions
    GROUP BY AccountID, CAST(TransactionTimestamp AS DATE)
),
GroupedSequences AS (
    SELECT AccountID, TradeDate, DayOutcome,
           ROW_NUMBER() OVER (PARTITION BY AccountID ORDER BY TradeDate) -
           ROW_NUMBER() OVER (PARTITION BY AccountID, DayOutcome ORDER BY TradeDate) AS IslandID
    FROM DailyPnL
)
SELECT AccountID, DayOutcome, MIN(TradeDate) AS StreakStart, MAX(TradeDate) AS StreakEnd, COUNT(*) AS StreakDays
FROM GroupedSequences
WHERE DayOutcome = 'PROFIT'
GROUP BY AccountID, DayOutcome, IslandID
HAVING COUNT(*) >= 3;
Subtracting partitioned row numbers groups consecutive matches into unique islands.

Q40: Multiple CTE References in a Single Execution Scope
Easy

WITH BuyOrders AS (
    SELECT AccountID, SUM(Quantity) AS TotalBuyQty FROM Orders WHERE OrderSide = 'BUY' GROUP BY AccountID

Q42: Inline Table-Valued Function (iTVF) vs Multi-Statement TVF (mTVF)
Medium

Demonstrate the syntax difference and explain why iTVF enables parallel query plans while mTVF blocks them.

💡 View Solution & Explanation ▼ 
-- Inline TVF (Optimizer treats as a view):
CREATE FUNCTION dbo.fn_Orders_iTVF (@AccountID INT)
RETURNS TABLE AS
RETURN (SELECT OrderID, Quantity, LimitPrice FROM Orders WHERE AccountID = @AccountID);
GO

-- Multi-Statement TVF (Uses hidden table variable - lacks statistics):
CREATE FUNCTION dbo.fn_Orders_mTVF (@AccountID INT)
RETURNS @Result TABLE (OrderID BIGINT, Quantity INT, LimitPrice DECIMAL(18,4)) AS
BEGIN
    INSERT INTO @Result SELECT OrderID, Quantity, LimitPrice FROM Orders WHERE AccountID = @AccountID;
    RETURN;
END;
GO
Inline TVFs are directly inlined into the outer query's plan; mTVFs create hidden table variables that prevent parallelism.

Q45: Enterprise TRY...CATCH with THROW and XACT_STATE()
Hard

Write a transactional procedure that handles uncommittable transactions (XACT_STATE() = -1) and re-throws errors.

💡 View Solution & Explanation ▼ 
CREATE OR ALTER PROCEDURE usp_RobustFinancialAction
AS
BEGIN
    SET NOCOUNT ON;
    SET XACT_ABORT ON;

    BEGIN TRY
        BEGIN TRANSACTION;
            -- Action logic
        COMMIT TRANSACTION;
    END TRY
    BEGIN CATCH
        IF XACT_STATE() <> 0
            ROLLBACK TRANSACTION;
        THROW; -- Preserves original line number and error message!
    END CATCH
END;
GO
XACT_STATE() = -1 indicates a doomed transaction. THROW; re-raises the exact original exception.

Q49: Querying sys.dm_exec_query_stats for Top CPU-Consuming Queries
Hard

Write a DMV query to find the top 5 worst queries by total CPU worker time, displaying the actual SQL text.

💡 View Solution & Explanation ▼ 
SELECT TOP (5)
    qs.total_worker_time / 1000 AS TotalCpuMs,
    qs.execution_count AS ExecCount,
    (qs.total_worker_time / qs.execution_count) / 1000 AS AvgCpuMs,
    qs.total_logical_reads / qs.execution_count AS AvgLogicalReads,
    SUBSTRING(st.text, (qs.statement_start_offset/2) + 1,
        ((CASE qs.statement_end_offset 
            WHEN -1 THEN DATALENGTH(st.text)
            ELSE qs.statement_end_offset END - qs.statement_start_offset)/2) + 1) AS QueryText
FROM sys.dm_exec_query_stats qs
CROSS APPLY sys.dm_exec_sql_text(qs.sql_handle) st
ORDER BY qs.total_worker_time DESC;
Calculates average CPU and logical reads per execution to locate resource-hogging queries.

Q51: Finding Wait Statistics (PAGEIOLATCH_SH vs SOS_SCHEDULER_YIELD)
Expert

Query sys.dm_os_wait_stats to identify whether the instance bottleneck is Disk I/O or CPU pressure.

💡 View Solution & Explanation ▼ 
SELECT TOP (10)
    wait_type,
    wait_time_ms / 1000.0 AS WaitTimeSeconds,
    (wait_time_ms - signal_wait_time_ms) / 1000.0 AS ResourceWaitSeconds,
    signal_wait_time_ms / 1000.0 AS SignalWaitSeconds -- Signal wait indicates CPU queueing!
FROM sys.dm_os_wait_stats
WHERE wait_type NOT IN (
    'CLR_SEMAPHORE','LAZYWRITER_SLEEP','RESOURCE_QUEUE','SLEEP_TASK','SLEEP_SYSTEMTASK',
    'SQLTRACE_BUFFER_FLUSH','WAITFOR','LOGMGR_QUEUE','CHECKPOINT_QUEUE','REQUEST_FOR_DEADLOCK_SEARCH'
)
ORDER BY wait_time_ms DESC;
PAGEIOLATCH_* signifies storage I/O bottleneck; high SOS_SCHEDULER_YIELD indicates CPU thread starvation.
Q52: Comprehensive Financial Settlement Audit Ledger Reconstruction
Expert

Write an end-to-end reconciliation query that compares opening cash balances, adds all deposits, subtracts all withdrawals and buys, adds sells and fees, and verifies whether the calculated sum matches the current physical CashBalance on every account.

💡 View Solution & Explanation ▼ 
WITH LedgerBreakdown AS (
    SELECT 
        AccountID,
        SUM(CASE WHEN TransactionType = 'DEPOSIT' THEN Amount ELSE 0 END) AS TotalDeposits,
        SUM(CASE WHEN TransactionType = 'WITHDRAWAL' THEN Amount ELSE 0 END) AS TotalWithdrawals,
        SUM(CASE WHEN TransactionType = 'TRADE_BUY' THEN Amount ELSE 0 END) AS TotalBuySpend,
        SUM(CASE WHEN TransactionType = 'TRADE_SELL' THEN Amount ELSE 0 END) AS TotalSellProceeds,
        SUM(CASE WHEN TransactionType = 'FEE' THEN Amount ELSE 0 END) AS TotalFees,
        SUM(Amount) AS NetLedgerTotal
    FROM LedgerTransactions
    GROUP BY AccountID
)
SELECT 
    a.AccountID,
    a.AccountNumber,
    a.CashBalance AS CurrentPhysicalBalance,
    ISNULL(l.NetLedgerTotal, 0.00) AS CalculatedLedgerBalance,
    (a.CashBalance - ISNULL(l.NetLedgerTotal, 0.00)) AS BalanceDiscrepancy,
    CASE 
        WHEN ABS(a.CashBalance - ISNULL(l.NetLedgerTotal, 0.00)) < 0.0001 THEN 'BALANCED_OK'
        ELSE 'AUDIT_ALERT_UNBALANCED'
    END AS ReconciliationStatus
FROM Accounts a
LEFT JOIN LedgerBreakdown l ON a.AccountID = l.AccountID
ORDER BY ABS(a.CashBalance - ISNULL(l.NetLedgerTotal, 0.00)) DESC;
Architectural Masterpiece: This query performs double-entry accounting reconciliation across the entire ledger. In financial audits, any row with AUDIT_ALERT_UNBALANCED isolates illegal state modifications or unlogged transactions immediately.
