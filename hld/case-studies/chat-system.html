Design a Chat System (WhatsApp / Messenger)

A chat system enables real-time text-based communication between users.

📖 Real-time: Data processing that appears to take place instantaneously upon data entry or receipt.

Step 1 — Requirements

Functional Requirements

  • 1-on-1 messaging
  • Group chat
  • Online/offline status indicator
  • Read receipts
  • Media sharing (images, videos)

Non-functional Requirements

  • Low latency delivery (<200ms)
  • High availability and persistence of chat history
  • Scale: 50M Daily Active Users (DAU)

Step 3 — Deep Dive

Connection Protocols

WebSocket

Bidirectional, persistent connection. Best for real-time chat.

HTTP Polling

Client repeatedly asks server for updates. Wastes bandwidth.

Message Storage

Chat applications generate a massive amount of data. We should use a NoSQL database like Cassandra or HBase for storing chat history because they are optimized for fast writes and time-series data.

Online Status

User status is tracked using a heartbeat mechanism. If the server stops receiving heartbeats for a certain period, the user is marked offline.

Step 4 — Implementation (Java 21)

Java 
import java.util.concurrent.ConcurrentHashMap;
import java.time.Instant;
import java.util.List;

// Java 21 Record for chat message
public record ChatMessage(String id, String senderId, String receiverId, String content, Instant timestamp) {}

// Sealed interface for delivery status
public sealed interface DeliveryStatus permits DeliveryStatus.Sent, DeliveryStatus.Delivered, DeliveryStatus.Read {
    record Sent() implements DeliveryStatus {}
    record Delivered(Instant time) implements DeliveryStatus {}
    record Read(Instant time) implements DeliveryStatus {}
}

interface MessageStore {
    void saveMessage(ChatMessage msg);
    List<ChatMessage> getHistory(String userId, int limit);
}

class OnlineStatusTracker {
    // Stores userId to last heartbeat timestamp
    private final ConcurrentHashMap<String, Instant> onlineUsers = new ConcurrentHashMap<>();
    private static final int OFFLINE_THRESHOLD_SECONDS = 30;

    public void heartbeat(String userId) {
        onlineUsers.put(userId, Instant.now());
    }

    public boolean isOnline(String userId) {
        Instant lastSeen = onlineUsers.get(userId);
        if (lastSeen == null) return false;
        return Instant.now().minusSeconds(OFFLINE_THRESHOLD_SECONDS).isBefore(lastSeen);
    }
}

class ChatServer {
    private final MessageStore store;
    private final OnlineStatusTracker statusTracker;

    public ChatServer(MessageStore store, OnlineStatusTracker statusTracker) {
        this.store = store;
        this.statusTracker = statusTracker;
    }

    public DeliveryStatus sendMessage(ChatMessage msg) {
        store.saveMessage(msg);
        
        if (statusTracker.isOnline(msg.receiverId())) {
            // Logic to push message to receiver via WebSocket
            return new DeliveryStatus.Delivered(Instant.now());
        } else {
            // Push notification to offline user
            return new DeliveryStatus.Sent();
        }
    }
}

Step 5 — Optimization

  • End-to-End Encryption: Only the sender and receiver hold the keys to decrypt the messages.
  • Message Pagination: Load chat history in chunks using cursor-based pagination.
  • Media Compression: Compress images and videos before sending to reduce bandwidth.
💡 Interview Tip: For group chats, explain "fan-out". When a message is sent to a group of 100 people, the server fans out 100 individual messages to the respective receivers.
