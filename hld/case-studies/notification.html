Design a Notification System

A notification system alerts users via various channels (Push, SMS, Email) about important events, messages, or promotions.

📖 Idempotency: The property of certain operations in mathematics and computer science whereby they can be applied multiple times without changing the result beyond the initial application. (e.g., ensuring a user isn't notified twice for the same event).

Step 1 — Requirements

Functional Requirements

  • Send notifications via Push (iOS/Android), SMS, and Email.
  • Respect user preferences (opt-outs, quiet hours).
  • Support templating for messages.

Non-functional Requirements

  • High reliability (at-least-once delivery).
  • Low latency (< 5 seconds delay for urgent messages).
  • Scale: 10 Million notifications per day.

Step 3 — Deep Dive

Deduplication

We must ensure we don't spam users with the same notification. We can generate a unique ID for each notification event and use a cache (like Redis) to store this ID for a short period. Before sending, we check if the ID exists in the cache.

Priority Queues

Not all notifications are equal. OTPs and security alerts are high priority and should bypass marketing emails. We use different message queues (e.g., Kafka topics or RabbitMQ queues) based on priority.

Step 4 — Implementation (Java 21)

Java 
import java.util.concurrent.TimeUnit;

// Java 21 Record for Notification
public record Notification(String id, String userId, String message, NotificationType type) {}

enum NotificationType { URGENT, PROMOTIONAL, TRANSACTIONAL }

// Sealed interface for notification channels
public sealed interface NotificationChannel permits PushChannel, SmsChannel, EmailChannel {
    boolean send(Notification notification);
}

final class PushChannel implements NotificationChannel {
    @Override public boolean send(Notification n) { 
        System.out.println("Sending Push: " + n.message()); return true; 
    }
}
final class SmsChannel implements NotificationChannel {
    @Override public boolean send(Notification n) { 
        System.out.println("Sending SMS: " + n.message()); return true; 
    }
}
final class EmailChannel implements NotificationChannel {
    @Override public boolean send(Notification n) { 
        System.out.println("Sending Email: " + n.message()); return true; 
    }
}

class DeduplicationFilter {
    public boolean isDuplicate(String notificationId) {
        // Check Redis or Cache to see if notificationId was processed recently
        return false;
    }
}

class RetryHandler {
    private static final int MAX_RETRIES = 3;

    public void executeWithRetry(Runnable action) {
        int attempt = 0;
        while (attempt < MAX_RETRIES) {
            try {
                action.run();
                return; // Success
            } catch (Exception e) {
                attempt++;
                try {
                    // Exponential backoff
                    Thread.sleep((long) Math.pow(2, attempt) * 1000);
                } catch (InterruptedException ie) {
                    Thread.currentThread().interrupt();
                }
            }
        }
        System.err.println("Failed after max retries. Sending to DLQ.");
    }
}

public class NotificationWorker {
    private final DeduplicationFilter filter = new DeduplicationFilter();
    private final RetryHandler retryHandler = new RetryHandler();

    public void processNotification(Notification n, NotificationChannel channel) {
        if (filter.isDuplicate(n.id())) {
            return;
        }

        retryHandler.executeWithRetry(() -> {
            boolean success = channel.send(n);
            if (!success) throw new RuntimeException("Delivery failed");
        });
    }
}

Step 5 — Optimization

  • Batch Processing: Batch non-urgent notifications (like weekly digests) to save bandwidth and compute.
  • Timezone Awareness: Don't send promotional notifications at 3 AM in the user's local timezone.
  • Analytics: Track delivery, open, and click rates to improve notification templates.
💡 Interview Tip: Always mention a Dead Letter Queue (DLQ) for failed notifications. This shows you think about error handling and system reliability in the real world.
