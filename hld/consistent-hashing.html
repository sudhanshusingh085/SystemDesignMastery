Consistent Hashing

Interview Tip: Consistent Hashing is the go-to answer whenever you are asked about partitioning or distributing data evenly across a dynamic pool of servers (like scaling a database or distributed cache).

The Problem: Traditional Hashing

Before understanding consistent hashing, we must ask: What is hashing?

📖 Hashing: Converting data (like a name or ID) into a fixed-size number. Think of it like a librarian assigning a unique shelf number to every book based on its title.

Imagine we have N 📖 Servers: Computers that process requests or store data. and we want to store user data across them. The simplest approach is to use a modulo operation:

serverIndex = hash(key) % N

This works fine until the number of servers changes. If a server crashes or we add a new one, N changes. Suddenly, almost every key hashes to a completely different server index. This means a massive data redistribution, which can overwhelm the network and take down the entire system in a cache miss storm.

What is Consistent Hashing?

Consistent hashing solves this problem by arranging the servers on a virtual circle, often called a hash ring. Both the servers and the data keys are hashed to points on this same circle.

To find which server should store a specific piece of data, we map the data's key to the ring, and then move clockwise until we find the first server. That server is responsible for the data.

How it minimizes redistribution

If a server is added, only the data between the new server and the previous server on the ring needs to be redistributed. If a server is removed, its data is simply taken over by the next server clockwise. The vast majority of keys stay exactly where they were.

Virtual Nodes

A problem with basic consistent hashing is that servers might not be evenly spaced on the ring, leading to unbalanced load (one server gets too much data). To fix this, we use Virtual Nodes.

📖 Virtual Nodes: Instead of placing a physical server on the ring once, we place it multiple times using different hash functions (e.g., Server1_A, Server1_B, Server1_C).

This creates a more uniform distribution. If a server is powerful, we can give it more virtual nodes. If it's weak, we give it fewer.

Step-by-step Walkthrough

1
Hash the Servers: We hash the IP or ID of each server (and its virtual node variants) to place them on the ring (0 to 2^32 - 1).
2
Hash the Data: When a request for a key comes in, we hash the key to find its position on the ring.
3
Route the Data: We scan clockwise from the data's position to find the first virtual node. We then route the request to the physical server that virtual node represents.

Java 21 Code Example

Here is a complete, beginner-friendly implementation of a Consistent Hash Ring using Java 21's features, specifically utilizing a TreeMap which is perfect for searching "the next element clockwise".

Java 
import java.security.MessageDigest;
import java.security.NoSuchAlgorithmException;
import java.util.SortedMap;
import java.util.TreeMap;

/**
 * A Consistent Hash Ring implementation.
 */
public class ConsistentHashRing {

    // Number of virtual nodes per physical server to ensure even distribution
    private final int virtualNodesPerServer;
    
    // TreeMap keeps the hashes sorted. It represents our hash ring.
    // Key: Hash value, Value: Physical Server Name
    private final SortedMap<Integer, String> ring = new TreeMap<>();

    public ConsistentHashRing(int virtualNodesPerServer) {
        this.virtualNodesPerServer = virtualNodesPerServer;
    }

    /**
     * Adds a new server to the ring.
     */
    public void addNode(String serverName) {
        for (int i = 0; i < virtualNodesPerServer; i++) {
            // Create a unique name for the virtual node
            String virtualNodeName = serverName + "-VN" + i;
            int hash = getHash(virtualNodeName);
            ring.put(hash, serverName);
        }
        System.out.println("Added server: " + serverName);
    }

    /**
     * Removes a server from the ring.
     */
    public void removeNode(String serverName) {
        for (int i = 0; i < virtualNodesPerServer; i++) {
            String virtualNodeName = serverName + "-VN" + i;
            int hash = getHash(virtualNodeName);
            ring.remove(hash);
        }
        System.out.println("Removed server: " + serverName);
    }

    /**
     * Finds the appropriate server for a given key.
     */
    public String getNode(String key) {
        if (ring.isEmpty()) {
            return null;
        }

        int hash = getHash(key);
        
        // Find all nodes whose hash is greater than or equal to the key's hash
        // This is like looking "clockwise" on the ring.
        SortedMap<Integer, String> tailMap = ring.tailMap(hash);
        
        // If tailMap is empty, it means we wrapped around the circle.
        // We take the first node in the ring.
        int targetHash = tailMap.isEmpty() ? ring.firstKey() : tailMap.firstKey();
        
        return ring.get(targetHash);
    }

    /**
     * Helper method to generate a hash. 
     * In a real system, use MD5 or MurmurHash. We use a simplified String hashCode here 
     * combined with MD5 for better distribution than standard Java hashCode.
     */
    private int getHash(String key) {
        try {
            MessageDigest md = MessageDigest.getInstance("MD5");
            md.update(key.getBytes());
            byte[] digest = md.digest();
            // Convert first 4 bytes to an integer
            return ((digest[3] & 0xFF) << 24) |
                   ((digest[2] & 0xFF) << 16) |
                   ((digest[1] & 0xFF) << 8) |
                   (digest[0] & 0xFF);
        } catch (NoSuchAlgorithmException e) {
            throw new RuntimeException("MD5 not supported", e);
        }
    }

    public static void main(String[] args) {
        ConsistentHashRing hashRing = new ConsistentHashRing(3); // 3 virtual nodes per server
        
        hashRing.addNode("Server-A");
        hashRing.addNode("Server-B");
        hashRing.addNode("Server-C");
        
        System.out.println("User 'Alice' goes to: " + hashRing.getNode("Alice"));
        System.out.println("User 'Bob' goes to: " + hashRing.getNode("Bob"));
        System.out.println("User 'Charlie' goes to: " + hashRing.getNode("Charlie"));
        
        // If Server-B crashes
        hashRing.removeNode("Server-B");
        
        System.out.println("After Server-B removed:");
        System.out.println("User 'Alice' goes to: " + hashRing.getNode("Alice"));
        System.out.println("User 'Bob' goes to: " + hashRing.getNode("Bob"));
    }
}

Where is Consistent Hashing Used?

Consistent hashing is a foundational concept used in many massively distributed systems:

  • NoSQL Databases: Amazon DynamoDB and Apache Cassandra use it to partition data across clusters of nodes.
  • Content Delivery Networks (CDNs): To distribute web traffic evenly across edge servers.
  • Distributed Caching: Systems like Memcached and Redis cluster use it to know which cache server holds a specific key.
  • Load Balancers: To ensure requests from a specific user always hit the same backend server (sticky sessions).
