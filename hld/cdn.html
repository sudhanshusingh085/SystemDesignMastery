Content Delivery Network (CDN)

What is a CDN?

A Content Delivery Network (CDN) is a geographically distributed network of proxy servers. Its goal is to provide high availability and high performance by distributing services spatially relative to end-users.

Real-World Analogy: Amazon Warehouses
Imagine you order a book from an online store whose only warehouse is in New York. If you live in Tokyo, that book will take days to arrive. To fix this, the store opens smaller warehouses in Tokyo, London, and Sydney, stocking them with the most popular books. Now, when you order in Tokyo, the book is shipped from the local Tokyo warehouse and arrives in a few hours. A CDN does exactly this, but for digital files.

Why do we need CDNs?

Physics matters. Data traveling over fiber-optic cables is fast, but it is bounded by the speed of light. Sending a large image from a server in London to a user in Australia introduces noticeable delay (latency). CDNs solve this.

  • Speed: Content is served from a server physically close to the user (an Edge Server).
  • Reduced Server Load: The CDN absorbs massive amounts of traffic, saving your main server (Origin Server) from being overwhelmed.
  • Reliability & Security: CDNs can handle hardware failures better due to their distributed nature and provide protection against DDoS attacks.

What goes on a CDN?

CDNs are designed for Static Content — files that don't change per user. This includes:

  • Images, Videos, and Audio
  • CSS stylesheets and JavaScript files
  • HTML pages (if they are static)

Dynamic content (like a user's bank account balance) is usually fetched directly from the Origin Server, though modern CDNs have features to optimize this too.

How a CDN Works (Step-by-Step)

1
A user in Paris visits a website. The browser requests an image (e.g., logo.png).
2
Through DNS routing, the request is directed to the nearest CDN Edge Server in Europe.
3
If the Edge Server has logo.png cached (a cache hit), it returns it immediately.
4
If not (a cache miss), the Edge Server requests the file from your Origin Server, caches it for future users, and returns it to the user.

Push vs Pull CDNs

  • Pull CDN: The most common. The edge server "pulls" the file from the origin server the first time a user requests it. Great for content with varying popularity.
  • Push CDN: You manually upload (push) the content to the CDN servers ahead of time. Good for large files (like software updates or games) that you know millions of people will download at the exact same time.

Java 21 Code Example: Simulating a CDN

Here is a simulation of how a CDN routes requests geographically and handles cache misses.

import java.util.HashMap;
import java.util.Map;

public class CdnSimulation {

    static class OriginServer {
        private final Map<String, String> database = new HashMap<>();

        public OriginServer() {
            database.put("/images/logo.png", "[Binary data of logo]");
            database.put("/css/style.css", "body { color: black; }");
        }

        public String fetchFile(String path) {
            System.out.println("  [ORIGIN SERVER] Serving file from main database: " + path);
            try { Thread.sleep(50); } catch (InterruptedException ignored) {}
            return database.getOrDefault(path, "404 Not Found");
        }
    }

    static class CdnNode {
        private final String region;
        private final OriginServer origin;
        private final Map<String, String> cache = new HashMap<>();

        public CdnNode(String region, OriginServer origin) {
            this.region = region;
            this.origin = origin;
        }

        public String requestFile(String path) {
            System.out.println("Request hitting " + region + " Edge Node for " + path);
            if (cache.containsKey(path)) {
                System.out.println("  ✓ [CACHE HIT] Serving quickly from edge.");
                return cache.get(path);
            }
            System.out.println("  ✗ [CACHE MISS] Fetching from Origin...");
            String fileData = origin.fetchFile(path);
            cache.put(path, fileData);
            return fileData;
        }
    }

    static class DnsRouter {
        private final Map<String, CdnNode> nodes = new HashMap<>();

        public void addNode(String region, CdnNode node) {
            nodes.put(region, node);
        }

        public CdnNode routeToNearestNode(String userRegion) {
            return nodes.getOrDefault(userRegion, nodes.get("USA"));
        }
    }

    public static void main(String[] args) {
        OriginServer origin = new OriginServer();
        CdnNode asiaNode = new CdnNode("Asia", origin);
        CdnNode europeNode = new CdnNode("Europe", origin);

        DnsRouter router = new DnsRouter();
        router.addNode("Asia", asiaNode);
        router.addNode("Europe", europeNode);

        System.out.println("--- User in Asia requests logo ---");
        CdnNode nodeForUser1 = router.routeToNearestNode("Asia");
        nodeForUser1.requestFile("/images/logo.png");

        System.out.println("\n--- ANOTHER User in Asia requests logo ---");
        nodeForUser1.requestFile("/images/logo.png"); // Hit!
    }
}
using System.Collections.Concurrent;

public class OriginServer
{
    private readonly Dictionary<string, string> _database = new()
    {
        ["/images/logo.png"] = "[Binary data of logo]",
        ["/css/style.css"] = "body { color: black; }"
    };

    public async Task<string> FetchFileAsync(string path)
    {
        Console.WriteLine($"  [ORIGIN SERVER] Serving file from master store: {path}");
        await Task.Delay(50); // Simulate high WAN latency
        return _database.GetValueOrDefault(path, "404 Not Found");
    }
}

public class CdnNode(string region, OriginServer origin)
{
    private readonly ConcurrentDictionary<string, string> _edgeCache = new();

    public async Task<string> RequestFileAsync(string path)
    {
        Console.WriteLine($"Request hitting {region} Edge Node for {path}");

        if (_edgeCache.TryGetValue(path, out var cached))
        {
            Console.WriteLine("  ✓ [CACHE HIT] Serving sub-millisecond from edge PoP.");
            return cached;
        }

        Console.WriteLine("  ✗ [CACHE MISS] Fetching across backbone from Origin...");
        var payload = await origin.FetchFileAsync(path);
        _edgeCache.TryAdd(path, payload);
        return payload;
    }
}

public class AnycastGeoRouter
{
    private readonly Dictionary<string, CdnNode> _nodes = new();

    public void RegisterPoP(string region, CdnNode node) => _nodes[region] = node;

    public CdnNode RouteToNearestPoP(string userRegion) =>
        _nodes.GetValueOrDefault(userRegion, _nodes["USA"]);
}

Popular CDN Providers

You rarely build a CDN from scratch. Most companies use third-party providers:

  • Cloudflare: Extremely popular, also acts as a security layer.
  • AWS CloudFront: Amazon's offering, integrates perfectly with S3 buckets.
  • Akamai: One of the oldest and largest enterprise CDNs.
Interview Tip: If the system design prompt mentions "Global users", "Read-heavy", or involves serving images/videos (like Instagram or Netflix), always include a CDN in your architecture diagram immediately. It's an easy win.
