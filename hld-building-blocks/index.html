HLD Building Blocks — Your Complete Toolbox

Welcome to the ultimate cheat sheet for High-Level Design (HLD). Think of these as the LEGO blocks of system design. Every component you might ever use to build a large-scale system is summarized here.

💡 How to use this page: Use this as a quick reference when designing systems. For deep dives, follow the links in each section!

Networking & Traffic 🌐

  • Client: Any application (mobile app, browser) making requests.
    Analogy: A customer at a restaurant.
  • API: Application Programming Interface; the contract between systems.
    Analogy: The menu at a restaurant.
  • HTTP/HTTPS: Protocol for sending data over the web (HTTPS is encrypted).
    Analogy: The language you speak to the waiter.
  • DNS: Domain Name System; translates domain names to IP addresses.
    Analogy: The phonebook of the internet.
  • TCP/UDP: Transport protocols. TCP is reliable, UDP is fast but unreliable.
    Analogy: TCP is a registered letter; UDP is a postcard.
  • Load Balancer: Distributes incoming traffic across multiple servers.
    Analogy: A traffic cop directing cars to different lanes.
  • Reverse Proxy: Sits in front of servers and forwards client requests to them.
    Analogy: A receptionist who takes your message and gives it to the right person.
  • CDN: Content Delivery Network; caches static assets near users globally.
    Analogy: Local vending machines stocked with popular drinks so you don't have to go to the main warehouse.
  • API Gateway: Single entry point for all API calls; handles routing, auth, rate limiting.
    Analogy: The front desk at a corporate office.
  • Service Discovery: Helps services find each other dynamically.
    Analogy: A live directory of extensions in an office.

Data Storage 💾

  • Database (SQL): Relational data, structured tables (e.g., PostgreSQL, MySQL).
    Analogy: A highly organized Excel spreadsheet with strict rules.
  • Database (NoSQL): Flexible schema, document/key-value storage (e.g., MongoDB, DynamoDB).
    Analogy: A filing cabinet where you can throw any document into a folder.
  • Read Replica: A copy of the database specifically for read operations.
    Analogy: A printed copy of a textbook for students to read, keeping the original safe.
  • Replication: Copying data across multiple servers for backup.
    Analogy: Making photocopies of important documents.
  • Sharding: Splitting database rows across multiple machines.
    Analogy: Storing books A-M in one room and N-Z in another.
  • Partitioning: Dividing large tables into smaller, manageable chunks.
    Analogy: Organizing a 10-year file archive by year.
  • Indexing: A data structure that improves data retrieval speed.
    Analogy: The index at the back of a textbook.
  • Object Storage (S3): Storing unstructured files (images, videos).
    Analogy: A massive warehouse for storing physical boxes of any size.
  • Search Engine (Elasticsearch): Specialized database for complex text search.
    Analogy: A digital librarian who can find a specific sentence in millions of books instantly.

Caching ⚡

  • Cache: Temporary, fast storage for frequently accessed data.
    Analogy: Keeping your keys in your pocket instead of a safe.
  • Redis/Memcached: Popular in-memory caching systems.
  • Cache-Aside: Application checks cache first, then database if miss.
  • Write-Through: Data is written to cache and database at the same time.
  • TTL (Time To Live): How long data stays in the cache before expiring.

Messaging 📨

  • Message Queue: Asynchronous communication buffer (e.g., RabbitMQ).
    Analogy: An inbox on a busy person's desk.
  • Kafka: Distributed event streaming platform.
    Analogy: A chronological journal of everything that happened in a company.
  • Pub-Sub: Publisher-Subscriber pattern; one sender, many listeners.
    Analogy: A radio station broadcasting to anyone tuned in.

Reliability 🛡️

  • Rate Limiter: Restricts number of requests per user/time.
    Analogy: A bouncer at a club limiting how fast people enter.
  • Circuit Breaker: Stops calls to a failing service to prevent cascading failures.
    Analogy: An electrical fuse that blows to prevent a house fire.
  • Retry / Timeout: Trying again / stopping after waiting too long.
  • Bulkhead: Isolating components so one failure doesn't crash everything.
    Analogy: Watertight compartments in a ship.
  • Distributed Lock: Ensuring only one process modifies a resource.

Distributed Patterns 🧩

  • CAP Theorem: You can only pick 2: Consistency, Availability, Partition Tolerance.
  • PACELC: Extension of CAP for latency considerations.
  • Idempotency: Performing an action multiple times yields the same result.
    Analogy: Pressing an elevator button multiple times doesn't call multiple elevators.
  • Saga / Outbox: Patterns for distributed transactions across microservices.

Observability & Security 🔐

  • Monitoring / Logging / Tracing: Knowing what's happening, keeping records, following a request's path.
  • SLI/SLO/SLA: Service Level Indicator/Objective/Agreement (Metrics, goals, promises).
  • OAuth / JWT: Delegated access and stateless authentication tokens.
