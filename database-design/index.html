2. Normalization

Normalization organizes a database into tables to reduce redundancy and improve data integrity.

  • 1NF (First Normal Form): Each column must contain atomic (indivisible) values. No lists in a column.
  • 2NF: Must be 1NF, and all non-key attributes must depend on the entire primary key.
  • 3NF: Must be 2NF, and no transitive dependencies (non-key attributes should not depend on other non-key attributes).

Why normalize? It reduces duplicate data and anomalies when updating, deleting, or inserting.

3. Denormalization

Sometimes, normalized data requires too many expensive JOINs. Denormalization intentionally adds redundancy back into the database to speed up read performance.

Example: Storing the `total_order_amount` on the `USER` table instead of calculating it from `ORDER` and `ORDER_ITEM` every time.

4. Indexing Deep Dive

An

📖 Index: A data structure (usually a B-Tree) that improves the speed of data retrieval operations.
is like the index at the back of a book. Instead of reading every page (a full table scan), you look up the word and jump straight to the page.

import java.util.*;

public class IndexSimulation {
    record User(int id, String email) {}
    
    public static void main(String[] args) {
        List<User> table = new ArrayList<>();
        Map<String, User> index = new HashMap<>(); // Simulating an index
        
        for (int i = 0; i < 1_000_000; i++) {
            User u = new User(i, "user" + i + "@test.com");
            table.add(u);
            index.put(u.email(), u);
        }
        
        String target = "user999999@test.com";
        
        // Full Table Scan - O(N)
        long startScan = System.nanoTime();
        User foundScan = table.stream().filter(u -> u.email().equals(target)).findFirst().orElse(null);
        System.out.println("Scan took: " + (System.nanoTime() - startScan) + " ns");
        
        // Index Lookup - O(1)
        long startIndex = System.nanoTime();
        User foundIndex = index.get(target);
        System.out.println("Index took: " + (System.nanoTime() - startIndex) + " ns");
    }
}
using System.Diagnostics;

public class IndexSimulation
{
    public record User(int Id, string Email);

    public static void Main()
    {
        var table = new List<User>(1_000_000);
        var index = new Dictionary<string, User>(1_000_000); // Hash index simulation

        for (int i = 0; i < 1_000_000; i++)
        {
            var u = new User(i, $"user{i}@test.com");
            table.Add(u);
            index[u.Email] = u;
        }

        string target = "user999999@test.com";

        // Full Table Scan - O(N) linear iteration
        var sw = Stopwatch.StartNew();
        var foundScan = table.FirstOrDefault(u => u.Email == target);
        sw.Stop();
        Console.WriteLine($"Full Table Scan: {sw.ElapsedTicks * 100} ns");

        // Index Lookup - O(1) dictionary seek
        sw.Restart();
        index.TryGetValue(target, out var foundIndex);
        sw.Stop();
        Console.WriteLine($"Index Lookup: {sw.ElapsedTicks * 100} ns");
    }
}

5. SQL vs NoSQL Deep Dive

FeatureSQL (Relational)NoSQL (Non-Relational)
StructureTable-based, fixed schemaDocument, Key-Value, Graph, Column
ScalingVertical (Scale Up)Horizontal (Scale Out)
PropertiesACID compliantOften BASE compliant (Eventual consistency)

Types of NoSQL

  • Key-Value (Redis): Extremely fast, great for caching.
  • Document (MongoDB): Stores JSON-like documents, flexible schema.
  • Column-Family (Cassandra): Great for heavy write loads and time-series data.
  • Graph (Neo4j): Excellent for highly connected data (social networks, recommendations).

6. Schema Design Patterns

  • Many-to-Many: Uses a junction/mapping table (e.g., `student_course`).
  • Polymorphic associations: A table that can relate to multiple other tables (e.g., a `comments` table linking to `posts` or `videos`).
  • Soft Delete: Adding a boolean `is_deleted` column instead of physically removing rows to keep history.
  • Audit Columns: Standard columns like `created_at`, `updated_at`, `created_by` for tracking changes.

7. Connection Pooling

Opening a database connection is expensive (network handshake, authentication). A

📖 Connection Pool: A cache of database connections maintained so that connections can be reused.
keeps connections open.

Analogy: It's like a taxi stand. Instead of calling a company and waiting for a new taxi to arrive for every trip, taxis are already waiting at the stand ready to go.

// Simplified Simulation
import java.util.concurrent.*;

public class ConnectionPoolSimulation {
    private final BlockingQueue<String> pool;

    public ConnectionPoolSimulation(int poolSize) {
        pool = new ArrayBlockingQueue<>(poolSize);
        for (int i = 0; i < poolSize; i++) {
            pool.offer("Connection-" + i);
        }
    }

    public String getConnection() throws InterruptedException {
        return pool.take(); // Blocks if empty
    }

    public void releaseConnection(String connection) {
        pool.offer(connection);
    }
}
using System.Threading.Channels;

public class ConnectionPoolSimulation
{
    private readonly Channel<string> _pool;

    public ConnectionPoolSimulation(int poolSize)
    {
        var options = new BoundedChannelOptions(poolSize)
        {
            FullMode = BoundedChannelFullMode.Wait
        };
        _pool = Channel.CreateBounded<string>(options);

        for (int i = 0; i < poolSize; i++)
        {
            _pool.Writer.TryWrite($"Connection-{i}");
        }
    }

    public async ValueTask<string> GetConnectionAsync(CancellationToken ct = default)
    {
        // Non-blocking async wait when pool is depleted
        return await _pool.Reader.ReadAsync(ct);
    }

    public async ValueTask ReleaseConnectionAsync(string connection)
    {
        await _pool.Writer.WriteAsync(connection);
    }
}

10. Repository Pattern Example

public record User(int id, String name) {}

public interface UserRepository {
    Optional<User> findById(int id);
    void save(User user);
}

// In-Memory implementation for testing
public class InMemoryUserRepository implements UserRepository {
    private final Map<Integer, User> store = new ConcurrentHashMap<>();

    @Override
    public Optional<User> findById(int id) {
        return Optional.ofNullable(store.get(id));
    }

    @Override
    public void save(User user) {
        store.put(user.id(), user);
    }
}
using System.Collections.Concurrent;

public record User(int Id, string Name);

public interface IUserRepository
{
    ValueTask<User?> FindByIdAsync(int id, CancellationToken ct = default);
    ValueTask SaveAsync(User user, CancellationToken ct = default);
}

// In-Memory concurrent thread-safe implementation
public class InMemoryUserRepository : IUserRepository
{
    private readonly ConcurrentDictionary<int, User> _store = new();

    public ValueTask<User?> FindByIdAsync(int id, CancellationToken ct = default)
    {
        _store.TryGetValue(id, out var user);
        return ValueTask.FromResult(user);
    }

    public ValueTask SaveAsync(User user, CancellationToken ct = default)
    {
        _store[user.Id] = user;
        return ValueTask.CompletedTask;
    }
}
