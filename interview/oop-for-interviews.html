Object-Oriented Programming (OOP) for Interviews

What is OOP? Object-Oriented Programming is a paradigm where code is organized around "objects"—entities that bundle data (state) and behavior (methods) together. It models real-world concepts to make code reusable and easier to reason about.

The 4 Pillars of OOP

1. Encapsulation

Hiding internal state and requiring all interaction to be performed through an object's methods. Analogy: A capsule pill; you swallow it without needing to know the chemical powder inside.

public class BankAccount {
    private double balance; // Hidden state

    public void deposit(double amount) {
        if (amount > 0) balance += amount; // Controlled access
    }
}
public class BankAccount {
    private decimal _balance; // Hidden private state

    public void Deposit(decimal amount) {
        if (amount > 0) _balance += amount; // Controlled mutation
    }
}

2. Abstraction

Hiding complex implementation details and showing only the essential features. Analogy: Driving a car; you press the accelerator without needing to understand fuel injection.

3. Inheritance

A mechanism where a new class derives properties and behaviors from an existing class. Analogy: A 'Dog' inherits traits from 'Animal'.

4. Polymorphism

The ability of different objects to respond to the same method call in their own way. Analogy: Asking a Dog to 'speak' results in a bark, while a Cat results in a meow.

Core OOP Constructs in Java 21

class

The basic building block. Use it when you have a complete, concrete implementation of an object.

abstract class

A

📖 abstract class: A blueprint that cannot be instantiated on its own. It can contain both complete methods (with bodies) and abstract methods (without bodies).

When to use: When you want to share code among several closely related classes.

public abstract class Vehicle {
    // Shared behavior
    public void startEngine() { System.out.println("Engine started"); }
    // Must be implemented by subclasses
    public abstract void drive();
}
public abstract class Vehicle {
    // Shared behavior
    public void StartEngine() => Console.WriteLine("Engine started");
    // Must be implemented by derived classes
    public abstract void Drive();
}

interface

A contract that defines a set of methods a class must implement. Unlike abstract classes, interfaces are primarily about defining what an object can do, not how it does it.

When to use: To define capabilities for disparate classes (e.g., `Flyable` for a Bird and an Airplane).

public interface PaymentProcessor {
    boolean processPayment(double amount);
}
public interface IPaymentProcessor {
    bool ProcessPayment(decimal amount);
}

final class

A class that cannot be subclassed. The `String` class in Java is final.

When to use: When you want to guarantee immutability or prevent modification of core behavior for security.

public final class Configuration {
    private final String url = "https://api.example.com";
}
// 'sealed' in C# prevents inheritance (equivalent to Java final)
public sealed class Configuration {
    private readonly string _url = "https://api.example.com";
}

sealed class (Java 17+)

Restricts which classes may extend or implement it. It provides a middle ground between completely open (regular class) and completely closed (final class).

When to use: When you have a known, fixed set of subclasses, enabling exhaustive pattern matching in `switch` statements.

public sealed class Shape permits Circle, Square {}

final class Circle extends Shape {}
final class Square extends Shape {}
// In C#, closed type hierarchies use abstract records/classes with sealed variants
public abstract record Shape
{
    public sealed record Circle(double Radius) : Shape;
    public sealed record Square(double Side) : Shape;
}

record (Java 16+)

A special kind of class designed to be a transparent carrier for immutable data. It automatically generates constructors, getters, `equals()`, `hashCode()`, and `toString()`.

When to use: For Data Transfer Objects (DTOs) or anytime you just need to hold data.

public record User(String id, String email) {}
// C# positional record: immutable value equality + non-destructive 'with'
public record User(string Id, string Email);

enum

A special type used to define a collection of constants. In Java, enums can have fields and methods.

public enum OrderStatus {
    PENDING(1), SHIPPED(2), DELIVERED(3);
    
    private final int code;
    OrderStatus(int code) { this.code = code; }
    public int getCode() { return code; }
}
// C# enum with explicit underlying integral values
public enum OrderStatus {
    Pending = 1,
    Shipped = 2,
    Delivered = 3
}

Generics

Allows classes and methods to operate on objects of various types while providing compile-time type safety.

public class Box<T> {
    private T item;
    public void set(T item) { this.item = item; }
    public T get() { return item; }
}
public class Box<T> {
    public T? Item { get; set; }
}

Comparison Table

Construct Can instantiate? Primary Use Case
Class Yes General purpose objects with state and behavior.
Abstract Class No Sharing common base code among related objects.
Interface No Defining a contract or capability.
Sealed Class No* Domain modeling with a strictly limited set of subtypes.
Record Yes Immutable data carriers (DTOs).
Enum Yes (internal) Fixed set of constants.

Interview Patterns: What to Use When

  • "Make it extensible so we can add new payment methods later." → Use an Interface.
  • "These three classes share 80% of the same logic." → Use an Abstract Class.
  • "The status can only be one of these three exact values." → Use an Enum or a Sealed Class.
  • "I just need an object to return multiple values from this method." → Use a Record.
