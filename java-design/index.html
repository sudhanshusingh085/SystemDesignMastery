1. Interfaces

What is it? An interface is a contract. It declares a set of methods that a class must implement.

When to use it? When you want to define "what" something can do, without worrying about "how" it does it. Perfect for loose coupling and mocking in tests.

Real-World Analogy

A power outlet standard. The wall provides an interface (two prongs, 120V). Any appliance that implements this interface (has a matching plug) can draw power, regardless of whether it's a toaster or a TV.

classDiagram class Flyable { <<interface>> +fly() } Flyable <|.. Bird Flyable <|.. Airplane

Figure 1: Interface Implementation

public interface Flyable {
    // Abstract method (implicitly public and abstract)
    void fly();
    
    // Default method (since Java 8)
    default void land() {
        System.out.println("Landing smoothly...");
    }
}

public class Bird implements Flyable {
    @Override
    public void fly() {
        System.out.println("Flapping wings.");
    }
}

public class Airplane implements Flyable {
    @Override
    public void fly() {
        System.out.println("Starting jet engines.");
    }
}
public interface IFlyable
{
    // Implicitly public abstract method
    void Fly();

    // Default interface implementation (C# 8+)
    void Land() => Console.WriteLine("Landing smoothly...");
}

public class Bird : IFlyable
{
    public void Fly() => Console.WriteLine("Flapping wings.");
}

public class Airplane : IFlyable
{
    public void Fly() => Console.WriteLine("Starting jet engines.");
}
Interview Tip: Mention Functional Interfaces in Java vs delegates / func in C# for first-class functional execution.

2. Abstract Classes

What is it? A class that cannot be instantiated on its own. It acts as a partial blueprint, allowing you to define some concrete methods and some abstract ones.

When to use it? When you have closely related classes that share code and a common core identity.

public abstract class Vehicle {
    protected String id;
    
    public Vehicle(String id) {
        this.id = id;
    }
    
    // Concrete method shared by all children
    public void startEngine() {
        System.out.println("Engine started for " + id);
    }
    
    // Abstract method that children MUST implement
    public abstract String fuelType();
}
// Primary constructor on abstract class in C# 12
public abstract class Vehicle(string id)
{
    protected string Id { get; } = id;

    // Concrete method shared by all children
    public void StartEngine() => Console.WriteLine($"Engine started for {Id}");

    // Abstract method that subclasses MUST implement
    public abstract string FuelType();
}

3. Final & Sealed (Immutability & Invariance)

What is it? A keyword that restricts modification. A final (Java) / sealed (C#) class cannot be extended. A method cannot be overridden. A variable/field cannot be reassigned.

When to use it? To enforce immutability, prevent inheritance for security reasons (like String), or ensure a method's logic isn't tampered with by subclasses.

Real-World Analogy

A sealed envelope. Once it's sealed (finalized), you cannot change what's inside without breaking it.

// Cannot be subclassed
public final class Configuration {
    // Cannot be reassigned
    private final String url;
    
    public Configuration(String url) {
        this.url = url;
    }
    
    // Subclasses couldn't override this even if the class wasn't final
    public final String getUrl() {
        return url;
    }
}
// sealed keyword prevents inheritance; readonly property prevents mutation
public sealed class Configuration(string url)
{
    public string Url { get; } = url;
}

4. Sealed Classes / Discriminated Unions

What is it? A feature that restricts which classes can extend a superclass. It gives you compiler-verified exhaustive control over type hierarchies.

When to use it? Domain modeling where you know all possible variants of a type (e.g., AST nodes, specific business events, result envelopes).

Real-World Analogy

An exclusive club with a guest list. Only the names on the permit list are allowed in.

// The guest list: only Circle, Rectangle, and Triangle can extend Shape
public sealed class Shape permits Circle, Rectangle, Triangle {}

public final class Circle extends Shape {
    double radius;
}

public final class Rectangle extends Shape {
    double w, h;
}

public non-sealed class Triangle extends Shape {
    // Anyone can extend Triangle now
}

// Java 21 Pattern Matching with Sealed Classes
public void printShapeInfo(Shape shape) {
    // Exhaustive switch: compiler verifies all branches!
    switch(shape) {
        case Circle c -> System.out.println("Circle radius: " + c.radius);
        case Rectangle r -> System.out.println("Rectangle w: " + r.w);
        case Triangle t -> System.out.println("Triangle");
    }
}
// Closed discriminated union pattern in C# 12
public abstract record Shape
{
    private Shape() { } // Closed private constructor prevents external subclassing

    public sealed record Circle(double Radius) : Shape;
    public sealed record Rectangle(double Width, double Height) : Shape;
    public record Triangle(double BaseLength, double Height) : Shape;
}

// C# 12 Pattern Matching switch expression
public static string PrintShapeInfo(Shape shape) => shape switch
{
    Shape.Circle c    => $"Circle radius: {c.Radius}",
    Shape.Rectangle r => $"Rectangle {r.Width}x{r.Height}",
    Shape.Triangle t  => $"Triangle base: {t.BaseLength}",
    _                 => throw new InvalidOperationException("Unreachable")
};

5. Enums

What is it? A special data type that enables for a variable to be a set of predefined constants.

When to use it? For things that have a fixed set of states: Days, Seasons, Order Statuses, Directions.

Real-World Analogy

The days of the week. There are exactly 7. You can't invent an 8th day.

public enum OrderStatus {
    CREATED("Order created, unpaid"),
    PAID("Payment received"),
    SHIPPED("On the way"),
    DELIVERED("Delivered successfully");
    
    private final String description;
    
    // Enum constructors are implicitly private
    OrderStatus(String description) {
        this.description = description;
    }
    
    public String getDescription() {
        return description;
    }
}
public enum OrderStatus
{
    Created,
    Paid,
    Shipped,
    Delivered
}

// C# 12 Extension method for rich enum behavior
public static class OrderStatusExtensions
{
    public static string GetDescription(this OrderStatus status) => status switch
    {
        OrderStatus.Created   => "Order created, unpaid",
        OrderStatus.Paid      => "Payment received",
        OrderStatus.Shipped   => "On the way",
        OrderStatus.Delivered => "Delivered successfully",
        _                     => status.ToString()
    };
}

6. Records & Data Carriers

What is it? A concise syntax for creating immutable data carriers. It automatically generates a constructor, getters/properties, value-based equals(), hashCode(), and toString().

When to use it? For DTOs, configurations, tuples, or any class whose primary purpose is to hold data.

Real-World Analogy

A shipping label. It just carries information (address, name). It doesn't perform actions, and once printed, it shouldn't be altered.

// Compact record definition in Java 21
public record Point(int x, int y) {
    // Compact constructor for boundary validation
    public Point {
        if (x < 0 || y < 0) {
            throw new IllegalArgumentException("Coordinates must be positive");
        }
    }
    
    public double distanceFromOrigin() {
        return Math.sqrt(x * x + y * y);
    }
}
// Positional readonly record struct for zero heap allocation (C# 12)
public readonly record struct Point(int X, int Y)
{
    public Point(int x, int y) : this()
    {
        ArgumentOutOfRangeException.ThrowIfNegative(x);
        ArgumentOutOfRangeException.ThrowIfNegative(y);
        X = x;
        Y = y;
    }

    public double DistanceFromOrigin() => Math.Sqrt(X * X + Y * Y);
}

7. Immutability & Defensive Copying

What is it? Designing an object so its state cannot change after construction.

Why does it matter? Thread safety without locking, cache friendliness, zero side effects, and safe concurrent access.

📖 Defensive Copy: Copying mutable objects when passing them in or out of an immutable class to prevent external modification.
public final class ImmutableUser {
    private final String name;
    private final List<String> roles;
    
    public ImmutableUser(String name, List<String> roles) {
        this.name = name;
        // Defensive copy on constructor input
        this.roles = List.copyOf(roles); 
    }
    
    public List<String> getRoles() {
        // Safe because List.copyOf creates an unmodifiable list
        return roles;
    }
}
using System.Collections.Immutable;

public sealed class ImmutableUser(string name, IEnumerable<string> roles)
{
    public string Name { get; } = name;
    
    // System.Collections.Immutable guarantees thread-safe immutability
    public ImmutableArray<string> Roles { get; } = [.. roles];
}

8. Generics & Constraints

What is it? Parameterized types. Writing reusable components that work with multiple types while enforcing compile-time type safety.

Real-World Analogy

A shipping container. The container can hold electronics, clothes, or food. It's a generic box, but when you label it "Box of Electronics", you know you shouldn't put food in it.

// Generic class
public class Box<T> {
    private T item;
    
    public void put(T item) { this.item = item; }
    public T get() { return item; }
}

// Bounded generic: Type must implement Comparable
public <T extends Comparable<T>> T findMax(List<T> list) {
    return Collections.max(list);
}
public class Box<T>
{
    public T? Item { get; set; }
}

// Bounded generic with where constraint in C# 12
public static T FindMax<T>(IEnumerable<T> list) where T : IComparable<T>
{
    return list.Max() ?? throw new InvalidOperationException("Empty collection");
}

9. Exception Design

What is it? Properly classifying and handling errors across boundaries in an application.

  • Recoverable / Business Exceptions: Errors expected in normal operations (e.g. insufficient funds, entity not found).
  • Fatal / Technical Exceptions: Infrastructure or unrecoverable bugs (e.g. database timeout, null pointer).
// Sealed exception hierarchy in Java 21
public sealed abstract class AppException extends RuntimeException 
    permits BusinessException, TechnicalException {
    
    public AppException(String message) {
        super(message);
    }
}

public final class BusinessException extends AppException {
    public BusinessException(String msg) { super(msg); }
}

public final class TechnicalException extends AppException {
    public TechnicalException(String msg) { super(msg); }
}
// Exception hierarchy in C# 12 using primary constructors
public abstract class AppException(string message, Exception? inner = null) 
    : Exception(message, inner);

public sealed class BusinessException(string message) 
    : AppException(message);

public sealed class TechnicalException(string message, Exception? inner = null) 
    : AppException(message, inner);
