Behavioral Design Patterns

Behavioral patterns are concerned with algorithms and the assignment of responsibilities between objects.

1. Observer

Lets you define a subscription mechanism to notify multiple objects about any events that happen to the object they're observing.

📖 Analogy: YouTube subscription. When a creator uploads a video, all subscribers get notified.
Java 21 
import java.util.ArrayList;
import java.util.List;

public interface Subscriber {
    void update(String news);
}

public interface Publisher {
    void subscribe(Subscriber s);
    void unsubscribe(Subscriber s);
    void notifySubscribers();
}

public class NewsAgency implements Publisher {
    private List subscribers = new ArrayList<>();
    private String news;
    
    public void setNews(String news) {
        this.news = news;
        notifySubscribers();
    }
    
    @Override
    public void subscribe(Subscriber s) { subscribers.add(s); }
    
    @Override
    public void unsubscribe(Subscriber s) { subscribers.remove(s); }
    
    @Override
    public void notifySubscribers() {
        for (Subscriber s : subscribers) {
            s.update(news);
        }
    }
}

2. Strategy

Lets you define a family of algorithms, put each of them into a separate class, and make their objects interchangeable.

📖 Analogy: Going to work. You can drive, bike, or take the bus. The destination is the same, but the strategy is different.
Java 21 
public interface PaymentStrategy {
    void pay(int amount);
}

public class CreditCardPayment implements PaymentStrategy {
    public void pay(int amount) { System.out.println("Paid " + amount + " using Credit Card."); }
}

public class PayPalPayment implements PaymentStrategy {
    public void pay(int amount) { System.out.println("Paid " + amount + " using PayPal."); }
}

public class ShoppingCart {
    private PaymentStrategy strategy;
    
    public void setPaymentStrategy(PaymentStrategy strategy) {
        this.strategy = strategy;
    }
    
    public void checkout(int amount) {
        strategy.pay(amount);
    }
}

3. Command

Turns a request into a stand-alone object that contains all information about the request.

📖 Analogy: A restaurant order slip. The waiter doesn't cook; they write the command on a slip and pass it to the kitchen.
Java 21 
public interface Command {
    void execute();
    void undo();
}

public class BoldCommand implements Command {
    private String text;
    public void execute() { System.out.println("Making text bold: " + text); }
    public void undo() { System.out.println("Reverting bold text: " + text); }
}

public class CommandHistory {
    private java.util.Stack history = new java.util.Stack<>();
    
    public void executeCommand(Command c) {
        c.execute();
        history.push(c);
    }
    
    public void undo() {
        if (!history.isEmpty()) {
            history.pop().undo();
        }
    }
}

4. State

Lets an object alter its behavior when its internal state changes. It appears as if the object changed its class.

📖 Analogy: A traffic light. It behaves differently when it is Red, Yellow, or Green.
Java 21 
public sealed interface VendingMachineState permits IdleState, HasMoneyState, DispensingState {
    void insertMoney();
    void dispenseProduct();
}

public final class IdleState implements VendingMachineState {
    public void insertMoney() { System.out.println("Money inserted. State changed to HasMoney."); }
    public void dispenseProduct() { System.out.println("Cannot dispense. Insert money first."); }
}

public final class HasMoneyState implements VendingMachineState {
    public void insertMoney() { System.out.println("Already has money."); }
    public void dispenseProduct() { System.out.println("Product dispensed. State changed to Dispensing."); }
}

public final class DispensingState implements VendingMachineState {
    public void insertMoney() { System.out.println("Please wait. Dispensing product."); }
    public void dispenseProduct() { System.out.println("Already dispensing."); }
}

5. Template Method

Defines the skeleton of an algorithm in the superclass but lets subclasses override specific steps of the algorithm without changing its structure.

📖 Analogy: A recipe template. All cakes need mixing, baking, and decorating, but each cake type does it differently.
Java 21 
public abstract class DataParser {
    // Template method
    public final void parseDataAndProcess() {
        readData();
        processData();
        writeData();
    }
    
    protected abstract void readData();
    protected abstract void processData();
    
    private void writeData() {
        System.out.println("Writing data to database (common step).");
    }
}

public class CsvParser extends DataParser {
    protected void readData() { System.out.println("Reading CSV file."); }
    protected void processData() { System.out.println("Processing CSV data."); }
}

public class JsonParser extends DataParser {
    protected void readData() { System.out.println("Reading JSON file."); }
    protected void processData() { System.out.println("Processing JSON data."); }
}
