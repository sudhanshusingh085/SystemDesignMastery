Design Patterns Overview

A Design Pattern is a general, reusable solution to a commonly occurring problem within a given context in software design.

What is a Design Pattern?

Think of a design pattern as a proven recipe for solving a common problem. It's not a finished piece of code that you can copy and paste; rather, it is a template or description of how to solve a problem that can be used in many different situations.

History

The concept of design patterns was popularized by the book "Design Patterns: Elements of Reusable Object-Oriented Software" published in 1994 by four authors referred to as the Gang of Four (GoF): Erich Gamma, Richard Helm, Ralph Johnson, and John Vlissides.

Categories of Design Patterns

When to use patterns

Design patterns are great when you face a known problem. However, avoid "Patternitis" — don't force a pattern where a simple solution would suffice. Use them to improve code readability and maintainability, not to make simple code complex.

Creational Patterns

Deal with object creation mechanisms, trying to create objects in a manner suitable to the situation.

Structural Patterns

Deal with object composition and typically identify simple ways to realize relationships between entities.

Behavioral Patterns

Deal with communication between objects, how objects interact and distribute responsibility.
