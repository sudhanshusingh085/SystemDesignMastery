SOLID Principles

SOLID is an acronym for five design principles intended to make software designs more understandable, flexible, and maintainable.

1. Single Responsibility Principle (SRP)

A class should have one, and only one, reason to change. In other words, a class should only have one job.

📖 Analogy: A chef should only cook, not also do the restaurant's accounting and clean the floors.

Bad Approach

Java 
public class UserService {
    public void registerUser(String username) {
        // 1. Handle user registration logic
    }
    public void sendEmail(String email) {
        // 2. Handle email sending
    }
    public void saveToDatabase(Object data) {
        // 3. Handle database operations
    }
}

Good Approach

Java 
public class AuthService {
    private final UserRepository repository;
    private final EmailService emailService;
    // Constructor omitted for brevity
    
    public void registerUser(String username, String email) {
        repository.save(username);
        emailService.sendWelcomeEmail(email);
    }
}

public class EmailService {
    public void sendWelcomeEmail(String email) { /* ... */ }
}

public class UserRepository {
    public void save(String username) { /* ... */ }
}

2. Open/Closed Principle (OCP)

Software entities should be open for extension, but closed for modification.

📖 Analogy: A power strip. You can plug in new devices (extension) without rewiring the house (modification).

Bad Approach

Java 
public class AreaCalculator {
    public double calculateArea(Object shape) {
        if (shape instanceof Circle c) {
            return Math.PI * c.radius() * c.radius();
        } else if (shape instanceof Rectangle r) {
            return r.width() * r.height();
        }
        return 0;
    }
}

Good Approach

Java 
public interface Shape {
    double calculateArea();
}

public record Circle(double radius) implements Shape {
    @Override
    public double calculateArea() {
        return Math.PI * radius * radius;
    }
}

public record Rectangle(double width, double height) implements Shape {
    @Override
    public double calculateArea() {
        return width * height;
    }
}

3. Liskov Substitution Principle (LSP)

Subtypes must be substitutable for their base types without altering the correctness of the program.

📖 Analogy: If you order a taxi, a luxury taxi should also work — it's still a taxi and behaves like one.

Bad Approach

Java 
public class Rectangle {
    protected int width, height;
    public void setWidth(int width) { this.width = width; }
    public void setHeight(int height) { this.height = height; }
}

public class Square extends Rectangle {
    @Override
    public void setWidth(int width) {
        this.width = width;
        this.height = width; // Breaking expected behavior
    }
}

Good Approach

Java 
public interface Shape {
    int getArea();
}

public record Rectangle(int width, int height) implements Shape {
    @Override
    public int getArea() { return width * height; }
}

public record Square(int side) implements Shape {
    @Override
    public int getArea() { return side * side; }
}

4. Interface Segregation Principle (ISP)

Clients should not be forced to depend on interfaces they do not use.

📖 Analogy: A restaurant menu shouldn't force you to order dessert just to get the main course.

Bad Approach

Java 
public interface Worker {
    void work();
    void eat();
    void sleep();
}

public class Robot implements Worker {
    public void work() { /* Working */ }
    public void eat() { throw new UnsupportedOperationException(); }
    public void sleep() { throw new UnsupportedOperationException(); }
}

Good Approach

Java 
public interface Workable {
    void work();
}

public interface Eatable {
    void eat();
}

public interface Sleepable {
    void sleep();
}

public class Robot implements Workable {
    @Override
    public void work() { /* Working */ }
}

5. Dependency Inversion Principle (DIP)

High-level modules should not depend on low-level modules. Both should depend on abstractions.

📖 Analogy: A lamp shouldn't be hardwired to one specific power plant — it uses a standard plug.

Bad Approach

Java 
public class OrderService {
    private MySqlDatabase database;

    public OrderService() {
        this.database = new MySqlDatabase(); // Tight coupling
    }
}

Good Approach

Java 
public interface Database {
    void save(Object data);
}

public class OrderService {
    private final Database database;

    // Injected via constructor
    public OrderService(Database database) {
        this.database = database;
    }
}
