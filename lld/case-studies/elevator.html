Design an Elevator System (Masterclass)

Phase 1: Ground-Zero Theory & The Pain Point

At its core, an elevator system is a hardware-software coordination problem. In plain English, we have a set of moving boxes (elevators) serving static locations (floors). The disaster scenario? If we don't manage scheduling effectively, we suffer from starvation, where requests at extreme floors are ignored while the elevator bounces between middle floors. Without concurrent state management, two requests could try to move the elevator in opposite directions simultaneously, causing system failure.

Requirement Gathering Dialogue

A senior engineer doesn't just start coding. They scope the problem.

  • Building properties: How many floors? How many elevators? (e.g., 50 floors, 4 elevators).
  • Capacity limits: What is the weight/person limit?
  • Traffic Patterns: Are there peak morning (up-peak) or evening (down-peak) modes?
  • Emergency Modes: Fire alarms, maintenance, VIP overrides.

Phase 2: Architectural Decision Rationales & Modifier Deep Dives

Designing this requires precise decision-making around data structures and object-oriented principles.

  • Why `ElevatorState` and `Direction` are enums? Enums in Java provide thread-safe singletons and compile-time type safety. MOVING_UP, MOVING_DOWN, IDLE, and MAINTENANCE are finite states. Using Strings would be a disaster for memory and comparison speed.
  • Why `DispatchStrategy` is an interface? By using the Strategy Pattern, we isolate the algorithm logic from the physical elevator mechanics. This allows swapping First-Come-First-Serve (FCFS) for SCAN/LOOK algorithms, or even advanced Destination Dispatch logic without modifying the elevator's core code.
  • Why `ElevatorCar` uses internal concurrent queues (`ConcurrentSkipListSet` or `PriorityQueue` with locks)? An elevator needs to process requests in a sorted order based on its current direction, not just the order they were received. Using a `TreeSet` (wrapped in locks) allows logarithmic time complexity for finding the next floor in the current direction.

Phase 3: Step-by-Step Evolution & Thought Process

How do we arrive at the perfect design? Let's trace the naive attempts.

Attempt 1: FCFS (First-Come, First-Serve)
We put all requests in a simple FIFO queue. If Floor 5 requests UP, then Floor 1 requests UP, the elevator goes to 5, then back down to 1. Result: Thrashing and terrible efficiency.

Attempt 2: SCAN Algorithm (Elevator Algorithm)
The elevator goes all the way up to the top floor, then all the way down. Result: Better, but it travels to the top floor even if the highest request is only on floor 5. Wastes time and energy.

Attempt 3: LOOK Algorithm (The Winner)
The elevator goes up as long as there are requests in that direction. Once the highest requested floor is reached, it reverses direction. This is what modern standard elevators use.

Phase 4: Concurrency & Algorithm Deep Dive

Handling simultaneous button presses is the hardest part. If a user presses the UP button on floor 3 while the elevator is at floor 2 moving up, the request must be safely injected into the elevator's internal memory without causing a ConcurrentModificationException or race condition. We use ReentrantLock to protect the shared sets (upDestinations and downDestinations) to ensure visibility and atomicity across threads.

Phase 5: Production-Grade Java 21 Code

import java.util.*;
import java.util.concurrent.locks.ReentrantLock;

// PILLAR 2: Enums for type safety and fast comparison
enum Direction { UP, DOWN, IDLE }
enum ElevatorState { MOVING, IDLE, MAINTENANCE }

// Java 21 Record for immutable data transfer
record ElevatorRequest(int floor, Direction direction) {}

// PILLAR 2: Strategy Pattern Interface
interface DispatchStrategy {
    ElevatorCar selectElevator(List<ElevatorCar> elevators, ElevatorRequest request);
}

// Concrete Strategy: Odd-Even, Zoned, or Nearest (Simplified Nearest shown here)
class NearestElevatorStrategy implements DispatchStrategy {
    @Override
    public ElevatorCar selectElevator(List<ElevatorCar> elevators, ElevatorRequest request) {
        // Advanced logic: check direction and distance. Simplified here for brevity.
        return elevators.stream()
            .filter(e -> e.getState() != ElevatorState.MAINTENANCE)
            .min(Comparator.comparingInt(e -> Math.abs(e.getCurrentFloor() - request.floor())))
            .orElseThrow(() -> new RuntimeException("No available elevators"));
    }
}

class ElevatorCar {
    private final int id;
    private int currentFloor = 0;
    private Direction currentDirection = Direction.IDLE;
    private ElevatorState state = ElevatorState.IDLE;
    
    // Concurrent access protection
    private final ReentrantLock lock = new ReentrantLock();
    
    // Treesets give us O(log N) insertions and allow us to pull the "next" floor easily.
    private final NavigableSet<Integer> upDestinations = new TreeSet<>();
    private final NavigableSet<Integer> downDestinations = new TreeSet<>(Collections.reverseOrder());

    public ElevatorCar(int id) { this.id = id; }

    // Thread-safe request addition
    public void addDestination(int floor) {
        lock.lock();
        try {
            if (floor > currentFloor) upDestinations.add(floor);
            else if (floor < currentFloor) downDestinations.add(floor);
        } finally {
            lock.unlock();
        }
    }

    // PILLAR 4: LOOK Algorithm execution step
    public void move() {
        lock.lock();
        try {
            if (currentDirection == Direction.UP || currentDirection == Direction.IDLE) {
                if (!upDestinations.isEmpty()) {
                    currentDirection = Direction.UP;
                    state = ElevatorState.MOVING;
                    currentFloor = upDestinations.pollFirst();
                    System.out.println("Elevator " + id + " stopping at floor " + currentFloor);
                } else if (!downDestinations.isEmpty()) {
                    currentDirection = Direction.DOWN;
                } else {
                    currentDirection = Direction.IDLE;
                    state = ElevatorState.IDLE;
                }
            } else if (currentDirection == Direction.DOWN) {
                if (!downDestinations.isEmpty()) {
                    currentFloor = downDestinations.pollFirst();
                    System.out.println("Elevator " + id + " stopping at floor " + currentFloor);
                } else {
                    currentDirection = Direction.UP; // Reverse look
                }
            }
        } finally {
            lock.unlock();
        }
    }

    public int getCurrentFloor() { return currentFloor; }
    public ElevatorState getState() { return state; }
}

class ElevatorController {
    private final List<ElevatorCar> elevators;
    private final DispatchStrategy strategy;

    public ElevatorController(List<ElevatorCar> elevators, DispatchStrategy strategy) {
        this.elevators = List.copyOf(elevators); // Immutable copy for safety
        this.strategy = strategy;
    }

    public void requestElevator(ElevatorRequest request) {
        ElevatorCar car = strategy.selectElevator(elevators, request);
        car.addDestination(request.floor());
    }
}
using System;
using System.Collections.Generic;

// PILLAR 2: Enums for type safety and clarity
public enum Direction { Up, Down, Idle }
public enum ElevatorState { Moving, Idle, Maintenance }

// PILLAR 3: Concrete Elevator Car encapsulating hardware sensors & motor
public class ElevatorCar
{
    private readonly object _lock = new();
    public int Id { get; }
    public int CurrentFloor { get; private set; }
    public Direction CurrentDirection { get; private set; }
    public ElevatorState State { get; private set; }
    public SortedSet Destinations { get; } = new();

    public ElevatorCar(int id)
    {
        Id = id;
        CurrentFloor = 0;
        CurrentDirection = Direction.Idle;
        State = ElevatorState.Idle;
    }

    public void AddDestination(int floor)
    {
        lock (_lock)
        {
            Destinations.Add(floor);
            UpdateDirection();
        }
    }

    private void UpdateDirection()
    {
        if (Destinations.Count == 0)
        {
            CurrentDirection = Direction.Idle;
            State = ElevatorState.Idle;
            return;
        }

        int next = Destinations.Min;
        if (next > CurrentFloor)
        {
            CurrentDirection = Direction.Up;
            State = ElevatorState.Moving;
        }
        else if (next < CurrentFloor)
        {
            CurrentDirection = Direction.Down;
            State = ElevatorState.Moving;
        }
    }

    public void StepSimulation()
    {
        lock (_lock)
        {
            if (Destinations.Count == 0) return;

            if (CurrentDirection == Direction.Up) CurrentFloor++;
            else if (CurrentDirection == Direction.Down) CurrentFloor--;

            Console.WriteLine($"[Elevator {Id}] at Floor {CurrentFloor} (Direction: {CurrentDirection})");

            if (Destinations.Contains(CurrentFloor))
            {
                Console.WriteLine($"[Elevator {Id}] Doors OPENING at Floor {CurrentFloor}. Passengers board/exit.");
                Destinations.Remove(CurrentFloor);
                UpdateDirection();
            }
        }
    }
}

// PILLAR 4: Strategy Pattern for dispatching algorithms (LOOK, SCAN, Shortest Seek)
public interface IDispatchStrategy
{
    ElevatorCar SelectElevator(List elevators, int floor, Direction direction);
}

public class NearestElevatorStrategy : IDispatchStrategy
{
    public ElevatorCar SelectElevator(List elevators, int floor, Direction direction)
    {
        ElevatorCar? best = null;
        int minDistance = int.MaxValue;

        foreach (var car in elevators)
        {
            if (car.State == ElevatorState.Maintenance) continue;

            // Simple proximity score: distance + penalty if moving opposite direction
            int distance = Math.Abs(car.CurrentFloor - floor);
            if (car.CurrentDirection != Direction.Idle && car.CurrentDirection != direction)
            {
                distance += 10; // Direction mismatch penalty
            }

            if (distance < minDistance)
            {
                minDistance = distance;
                best = car;
            }
        }
        return best ?? elevators[0];
    }
}

// PILLAR 5: Central Controller managing bank of elevators
public class ElevatorController
{
    private readonly List _elevators;
    private readonly IDispatchStrategy _strategy;

    public ElevatorController(int numCars, IDispatchStrategy strategy)
    {
        _elevators = new List();
        for (int i = 1; i <= numCars; i++)
        {
            _elevators.Add(new ElevatorCar(i));
        }
        _strategy = strategy;
    }

    public void RequestElevator(int floor, Direction direction)
    {
        Console.WriteLine($"External Hall Call: Floor {floor}, Direction: {direction}");
        var selected = _strategy.SelectElevator(_elevators, floor, direction);
        Console.WriteLine($"Dispatcher assigned Hall Call to Elevator {selected.Id}");
        selected.AddDestination(floor);
    }

    public void StepAll()
    {
        foreach (var car in _elevators)
        {
            car.StepSimulation();
        }
    }
}

public class Program
{
    public static void Main()
    {
        Console.WriteLine("Initializing Elevator System (2 Cars, 10 Floors)...");
        var controller = new ElevatorController(2, new NearestElevatorStrategy());

        controller.RequestElevator(5, Direction.Up);
        controller.RequestElevator(2, Direction.Down);

        // Run simulation steps
        for (int i = 0; i < 6; i++)
        {
            Console.WriteLine($"--- Clock Tick {i + 1} ---");
            controller.StepAll();
        }
    }
}

Phase 6: Trade-offs & The Interviewer's Deep Follow-Up Questions

The Grill Round

Interviewer: "What happens if there's a VIP override or emergency like a fire?"

Candidate: "We introduce a PriorityQueue for requests with an EmergencyLevel enum. In a fire, the strategy instantly flips all cars to MAINTENANCE or EMERGENCY_RETURN, discarding all queues and forcing movement to the ground floor."

Interviewer: "How do you optimize for morning peak traffic?"

Candidate: "We implement a Zoned Strategy. Elevators 1-2 only serve floors 1-20, and Elevators 3-4 serve 21-50. During peak hours, the controller pre-positions idle elevators at the lobby (floor 0) rather than leaving them at their last dropped-off floor."

Trade-offs: Lock contention on the ElevatorCar queues can become a bottleneck if there are thousands of simultaneous requests. In highly scaled environments (like simulating an entire city's elevators), an event-driven architecture using an actor model (like Akka) per elevator avoids lock contention entirely.
