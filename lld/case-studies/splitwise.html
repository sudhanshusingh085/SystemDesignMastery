Design Splitwise

Scenario: Design an expense sharing application like Splitwise where users can add expenses, split them using various strategies, and simplify their debts.

1. What is Splitwise?

Splitwise is an app that allows groups of friends to split expenses. For example, if Alice pays $100 for dinner for herself, Bob, and Charlie, Splitwise tracks that Bob and Charlie each owe Alice $33.33.

📖 Debt Simplification: Reducing the total number of transactions needed to settle up. If A owes B $10, and B owes C $10, it simplifies to A owing C $10.

2. What problem does it solve?

Tracking manual IOUs is prone to errors. Managing different splitting methods (Equal, Exact, Percentages) requires a flexible structure that allows extending logic without breaking the system.

import java.util.*;
import java.time.LocalDateTime;

record UserId(String id) {}
class User {
    String id, name, email;
    public User(String id, String name, String email) {
        this.id = id; this.name = name; this.email = email;
    }
}

// Design Pattern: Strategy — interchangeable algorithms for splitting
// SOLID: Open/Closed — new types extend without modifying existing code
sealed interface SplitStrategy permits EqualSplit, PercentageSplit, ExactSplit {
    Map<UserId, Double> calculateSplits(double totalAmount, List<UserId> participants);
}

record EqualSplit() implements SplitStrategy {
    @Override
    public Map<UserId, Double> calculateSplits(double totalAmount, List<UserId> participants) {
        double splitAmount = totalAmount / participants.size();
        Map<UserId, Double> splits = new HashMap<>();
        for (UserId u : participants) splits.put(u, splitAmount);
        return splits;
    }
}

record PercentageSplit(Map<UserId, Double> percentages) implements SplitStrategy {
    @Override
    public Map<UserId, Double> calculateSplits(double totalAmount, List<UserId> participants) {
        Map<UserId, Double> splits = new HashMap<>();
        for (UserId u : participants) {
            splits.put(u, (percentages.getOrDefault(u, 0.0) / 100.0) * totalAmount);
        }
        return splits;
    }
}

record ExactSplit(Map<UserId, Double> amounts) implements SplitStrategy {
    @Override
    public Map<UserId, Double> calculateSplits(double totalAmount, List<UserId> participants) {
        return amounts; // In real life, validate sum equals totalAmount
    }
}

record Expense(String id, String description, double amount, UserId paidBy, SplitStrategy strategy, List<UserId> participants, LocalDateTime timestamp) {}

class Group {
    String groupId, name;
    List<UserId> members = new ArrayList<>();
    List<Expense> expenses = new ArrayList<>();
}

// SOLID: Single Responsibility — this class only handles balance calculation and debt tracking
class BalanceSheet {
    // Map of user -> (Map of who they owe -> amount)
    private Map<UserId, Map<UserId, Double>> balances = new HashMap<>();

    public void updateBalances(Expense expense) {
        Map<UserId, Double> splits = expense.strategy().calculateSplits(expense.amount(), expense.participants());
        UserId paidBy = expense.paidBy();
        
        for (Map.Entry<UserId, Double> split : splits.entrySet()) {
            UserId owes = split.getKey();
            if (owes.equals(paidBy)) continue;
            
            double amountOwed = split.getValue();
            balances.putIfAbsent(owes, new HashMap<>());
            balances.putIfAbsent(paidBy, new HashMap<>());
            
            balances.get(owes).put(paidBy, balances.get(owes).getOrDefault(paidBy, 0.0) + amountOwed);
            balances.get(paidBy).put(owes, balances.get(paidBy).getOrDefault(owes, 0.0) - amountOwed);
        }
    }
    
    public void printBalances() {
        System.out.println("Current Balances: " + balances);
    }

    }
}

// Design Pattern: Observer — notify subscribers on state change
interface ExpenseObserver {
    void onExpenseAdded(Expense expense);
}

class NotificationService implements ExpenseObserver {
    @Override
    public void onExpenseAdded(Expense expense) {
        System.out.println("Notification: Expense '" + expense.description() + "' added!");
    }
}

// Design Pattern: Facade
class ExpenseService {
    private BalanceSheet balanceSheet = new BalanceSheet();
    private List<ExpenseObserver> observers = new ArrayList<>();
    
    public void addObserver(ExpenseObserver obs) { observers.add(obs); }
    
    public void addExpense(Expense expense) {
        balanceSheet.updateBalances(expense);
        for (ExpenseObserver obs : observers) obs.onExpenseAdded(expense);
    }
    
    public void showBalances() { balanceSheet.printBalances(); }
}

public class Main {
    public static void main(String[] args) {
        UserId u1 = new UserId("U1"); UserId u2 = new UserId("U2"); UserId u3 = new UserId("U3");
        ExpenseService service = new ExpenseService();
        service.addObserver(new NotificationService());
        
        Expense e1 = new Expense("E1", "Dinner", 300, u1, new EqualSplit(), List.of(u1, u2, u3), LocalDateTime.now());
        service.addExpense(e1);
        service.showBalances();
    }
}

5. Why is this recommended?

Using the Strategy Pattern for splits makes adding new split types (like "shares") trivial. The Observer Pattern perfectly models the real-world requirement of pushing notifications to users.

Interview Tip: The debt simplification algorithm is a common graph problem. Mention that it can be solved by calculating the "net balance" for each node (user), separating them into debtors and creditors, and greedily matching the largest debtor with the largest creditor using a Min/Max Heap.
