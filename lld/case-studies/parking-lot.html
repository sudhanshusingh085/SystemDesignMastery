Design a Parking Lot System — Machine Coding Masterclass

The LLD Crucible: The Parking Lot is the most frequently asked Machine Coding question in Amazon, Uber, and Microsoft interviews. In this exhaustive masterclass, we will traverse through requirement clarification, deep architectural entity modeling, thread-safety, and production-ready Java 21 implementation.

Phase 1: Interview Dialogue & Clarifying Requirements

Never jump straight into coding. The interviewer is testing your ability to handle ambiguity and scope a problem.

The Clarification Script

Candidate: "Does the parking lot have multiple floors, or is it a single flat level?"
Interviewer: "It has multiple floors."

Candidate: "What types of vehicles are we supporting, and do spots have sizes?"
Interviewer: "We support Motorcycles, Cars, and Trucks. Spots are Compact, Regular, and Large."

Candidate: "Can a Motorcycle park in a Large spot if no Compact spots are available?"
Interviewer: "No, let's keep it strict 1-to-1 mapping for simplicity."

Candidate: "What is our spot assignment strategy? Nearest to the entry gate, or random?"
Interviewer: "Nearest to the entry gate. But design it so the strategy can be easily swapped."

Candidate: "How is the fee calculated?"
Interviewer: "Hourly based on vehicle type. Again, make it flexible."

Candidate: "Is there a reservation system for booking spots ahead of time?"
Interviewer: "No, just physical drive-ins."

Candidate: "Can multiple cars enter via multiple gates simultaneously?"
Interviewer: "Yes! The system must handle high concurrency safely."

System Requirements Scoped

  • Functional: Multi-floor, specific vehicle-to-spot mapping, ticket issuance, dynamic fee calculation, multiple entry/exit gates.
  • Non-Functional: Thread-safe spot allocation, highly extensible for new pricing or allocation algorithms (SOLID).

Phase 2: Core Domain Entity Modeling & Thought Process

Here we dictate the structural architecture and justify every Java keyword used.

  • `Vehicle` (Abstract Class): Why not an interface? Because all vehicles share intrinsic state (license plate, vehicle type). An abstract class allows us to centralize this state while forcing concrete classes to specify their type.
  • `Car`, `Bike`, `Truck` (Final Classes): Why final? To prevent arbitrary, deep inheritance hierarchies. A `Car` should not be extended by `SportsCar`. We favor composition over deep inheritance.
  • `VehicleType`, `SpotType` (Enum): Why enums? The types are fixed domain constants. Enums provide compile-time safety and work perfectly with Java 21's enhanced `switch` expressions.
  • `Ticket` (Java 21 Record): Why a record? A ticket is a Data Transfer Object (DTO). Once issued, it should be entirely immutable. Records provide thread-safe immutability and auto-generate `equals/hashCode/toString` cleanly.
  • `ParkingStrategy` & `FeeStrategy` (Interfaces): We use the Strategy Pattern. The interviewer explicitly asked for flexible algorithms. Interfaces allow us to swap "Nearest Spot" for "Random Spot" without touching core logic (Open/Closed Principle).
  • `ParkingLot` (Singleton): The central orchestrator. It must be a thread-safe Singleton because there is exactly one physical parking lot managing the shared state of available spots.

Phase 4: Concurrency & Thread-Safety Design

The Nightmare Scenario: 10 cars arrive at 10 different entry gates at the exact same millisecond. There is only 1 Compact spot left. If you just iterate and check `if(spot.isFree())`, all 10 threads read `true`, and 10 cars are assigned the same physical spot. Catastrophe.

The Solution: The critical section is reserving the spot. We must use a ReentrantLock at the ParkingLot level or make the spot assignment atomic. In our code, we will synchronize the spot finding and reservation block to guarantee mutually exclusive access to the pool of free spots.

Phase 5: Complete, Robust Java 21 Code

Java 21 

import java.time.LocalDateTime;
import java.time.Duration;
import java.util.*;
import java.util.concurrent.locks.Lock;
import java.util.concurrent.locks.ReentrantLock;

// --- ENUMS ---
enum VehicleType { BIKE, CAR, TRUCK }
enum SpotType { COMPACT, REGULAR, LARGE }
enum PaymentStatus { PENDING, COMPLETED, FAILED }

// --- DOMAIN ENTITIES ---
// OOP: Abstraction & Encapsulation
abstract sealed class Vehicle permits Bike, Car, Truck {
    private final String licensePlate;
    private final VehicleType type;

    protected Vehicle(String licensePlate, VehicleType type) {
        this.licensePlate = licensePlate;
        this.type = type;
    }
    public String getLicensePlate() { return licensePlate; }
    public VehicleType getType() { return type; }
}

final class Bike extends Vehicle {
    public Bike(String licensePlate) { super(licensePlate, VehicleType.BIKE); }
}
final class Car extends Vehicle {
    public Car(String licensePlate) { super(licensePlate, VehicleType.CAR); }
}
final class Truck extends Vehicle {
    public Truck(String licensePlate) { super(licensePlate, VehicleType.TRUCK); }
}

// SOLID: SRP - ParkingSpot only manages its own state
class ParkingSpot {
    private final String spotId;
    private final SpotType type;
    private boolean isFree;
    private Vehicle vehicle;

    public ParkingSpot(String spotId, SpotType type) {
        this.spotId = spotId;
        this.type = type;
        this.isFree = true;
    }

    public boolean isFree() { return isFree; }
    public SpotType getType() { return type; }
    public String getSpotId() { return spotId; }

    public synchronized void assignVehicle(Vehicle vehicle) {
        this.vehicle = vehicle;
        this.isFree = false;
    }

    public synchronized void removeVehicle() {
        this.vehicle = null;
        this.isFree = true;
    }
}

// --- STRATEGY PATTERNS (SOLID: OCP) ---
interface ParkingStrategy {
    ParkingSpot findSpot(List<ParkingFloor> floors, SpotType type);
}

class NearestFirstParkingStrategy implements ParkingStrategy {
    @Override
    public ParkingSpot findSpot(List<ParkingFloor> floors, SpotType type) {
        for (ParkingFloor floor : floors) {
            for (ParkingSpot spot : floor.getSpots()) {
                if (spot.getType() == type && spot.isFree()) {
                    return spot;
                }
            }
        }
        return null;
    }
}

interface FeeStrategy {
    double calculateFee(LocalDateTime entryTime, LocalDateTime exitTime, VehicleType type);
}

class HourlyFeeStrategy implements FeeStrategy {
    @Override
    public double calculateFee(LocalDateTime entryTime, LocalDateTime exitTime, VehicleType type) {
        long hours = Duration.between(entryTime, exitTime).toHours();
        hours = Math.max(hours, 1); // minimum 1 hour charge
        return switch(type) {
            case BIKE -> hours * 10.0;
            case CAR -> hours * 20.0;
            case TRUCK -> hours * 30.0;
        };
    }
}

// Java 21 Record for pure DTO Immutability
record Ticket(String ticketId, String licensePlate, String spotId, LocalDateTime entryTime) {}

// --- COMPOSITE ENTITIES ---
class ParkingFloor {
    private final int floorNumber;
    private final List<ParkingSpot> spots = new ArrayList<>();

    public ParkingFloor(int floorNumber, int capacity) {
        this.floorNumber = floorNumber;
        for (int i = 1; i <= capacity; i++) {
            SpotType type = (i % 3 == 0) ? SpotType.LARGE : (i % 2 == 0) ? SpotType.REGULAR : SpotType.COMPACT;
            spots.add(new ParkingSpot(floorNumber + "-" + i, type));
        }
    }
    public List<ParkingSpot> getSpots() { return spots; }
}

// --- CORE SYSTEM CONTEXT (SINGLETON) ---
class ParkingLot {
    private static ParkingLot instance;
    private final List<ParkingFloor> floors;
    private final ParkingStrategy parkingStrategy;
    
    // Concurrency Lock for thread-safe assignment
    private final Lock assignmentLock = new ReentrantLock();

    private ParkingLot(int numFloors, int spotsPerFloor) {
        floors = new ArrayList<>();
        for (int i = 1; i <= numFloors; i++) {
            floors.add(new ParkingFloor(i, spotsPerFloor));
        }
        this.parkingStrategy = new NearestFirstParkingStrategy();
    }

    public static synchronized ParkingLot getInstance(int numFloors, int spotsPerFloor) {
        if (instance == null) {
            instance = new ParkingLot(numFloors, spotsPerFloor);
        }
        return instance;
    }

    private SpotType getSpotTypeForVehicle(VehicleType vType) {
        return switch (vType) {
            case BIKE -> SpotType.COMPACT;
            case CAR -> SpotType.REGULAR;
            case TRUCK -> SpotType.LARGE;
        };
    }

    // Thread-safe entry logic
    public Ticket parkVehicle(Vehicle vehicle) {
        SpotType requiredType = getSpotTypeForVehicle(vehicle.getType());
        
        assignmentLock.lock();
        try {
            ParkingSpot spot = parkingStrategy.findSpot(floors, requiredType);
            if (spot == null) {
                throw new RuntimeException("Parking Lot Full for vehicle type: " + vehicle.getType());
            }
            spot.assignVehicle(vehicle);
            String ticketId = UUID.randomUUID().toString();
            return new Ticket(ticketId, vehicle.getLicensePlate(), spot.getSpotId(), LocalDateTime.now());
        } finally {
            assignmentLock.unlock();
        }
    }

    public double unparkVehicle(Ticket ticket, FeeStrategy feeStrategy) {
        // Free up the spot
        for (ParkingFloor floor : floors) {
            for (ParkingSpot spot : floor.getSpots()) {
                if (spot.getSpotId().equals(ticket.spotId())) {
                    spot.removeVehicle();
                    break;
                }
            }
        }
        // Simulated vehicle lookup - in reality, link ticket to vehicle type
        return feeStrategy.calculateFee(ticket.entryTime(), LocalDateTime.now().plusHours(3), VehicleType.CAR);
    }
}

// --- MAIN SIMULATION ---
public class Main {
    public static void main(String[] args) {
        System.out.println("Initializing Parking Lot with 2 floors, 6 spots each...");
        ParkingLot lot = ParkingLot.getInstance(2, 6);

        Vehicle myCar = new Car("CA-1234");
        System.out.println("Attempting to park Car: CA-1234...");
        
        Ticket ticket = lot.parkVehicle(myCar);
        System.out.println("Parked successfully! Ticket Details: " + ticket);

        System.out.println("Processing Exit...");
        FeeStrategy hourlyBilling = new HourlyFeeStrategy();
        double fee = lot.unparkVehicle(ticket, hourlyBilling);
        
        System.out.println("Unparked successfully. Total Fee: $" + fee);
    }
}

Phase 6: The Interviewer's Deep Follow-Up Questions ("The Grill Round")

Q1: "How would you handle electric vehicle (EV) charging spots with metered electricity billing?"

A: We adhere to OCP. We add a new enum value `SpotType.EV_CHARGING`. We update the `ParkingStrategy` to route EVs to these spots. For billing, we use the Decorator Pattern on `FeeStrategy`. We wrap the base `HourlyFeeStrategy` inside a `MeteredElectricityFeeDecorator`, which adds the kWh usage cost to the base time cost.

Q2: "How do you scale this from a single parking garage to a distributed network of 500 parking garages across a city?"

A: This transitions from LLD to HLD. We drop the Singleton `ParkingLot` because state is no longer local to one JVM. We introduce a distributed database (like PostgreSQL or Cassandra) to hold spot state. We replace the `ReentrantLock` with Distributed Locking (e.g., Redis Redlock or ZooKeeper) or Optimistic Concurrency Control using a version column in the database (`UPDATE spot SET free=false WHERE id=1 AND version=2`) to prevent double-booking across 500 physical locations.

Q3: "What if the power goes out or a gate scanner crashes while a car is exiting?"

A: We need to design for Idempotency and State Recovery. The ticket and payment transaction must be logged in a persistent ACID database before opening the physical boom gate. If the system crashes, the retry mechanism checks the database state (e.g., `PaymentStatus.COMPLETED`) and triggers the gate open command without double-charging the customer.
