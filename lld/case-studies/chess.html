Design a Chess Game (LLD)

Scenario: Design a classic 8x8 Chess game for 2 players. Include pieces with unique move sets, turn-based logic, check/checkmate detection, and move validation.

1. What is a Chess Game System?

Think of it like an organized battlefield governed by strict rules. The

📖 Board: The 8x8 grid where pieces move.
acts as the terrain, and the players are the commanders.

A good design will manage the state of the game without tightly coupling the game loop to the individual piece behaviors.

2. What problem does it solve?

  • State Management: Keeping track of where every piece is.
  • Rule Enforcement: Ensuring pieces only make legal moves.
  • Game Progression: Alternating turns and checking for win/draw conditions like checkmate or stalemate.

import java.util.List;
import java.util.ArrayList;

// SOLID: SRP — Enums cleanly define specific constant categories
enum Color { WHITE, BLACK }

// Java 21 Record for immutable coordinates
record Position(int row, int col) {
    public Position {
        if (row < 0 || row > 7 || col < 0 || col > 7) {
            throw new IllegalArgumentException("Position out of bounds");
        }
    }
}

// SOLID: OCP — New pieces can extend this without modifying the Board or Game classes.
// SOLID: Liskov — Any Piece subclass can be used polymorphically anywhere a Piece is expected.
abstract class Piece {
    protected Color color;
    protected Position position;
    
    public Piece(Color color, Position position) {
        this.color = color;
        this.position = position;
    }
    
    public Color getColor() { return color; }
    public Position getPosition() { return position; }
    public void setPosition(Position position) { this.position = position; }
    
    // Abstract method to let each piece define its own movement logic (Polymorphism)
    public abstract List getValidMoves(Board board);
}

// Java 21 Sealed Interfaces: restricts which classes can implement it
// Ideal for representing distinct, closed sets of states like game phases.
sealed interface GameStatus permits InProgress, Check, Checkmate, Stalemate, Resignation {}
record InProgress() implements GameStatus {}
record Check(Player checkedPlayer) implements GameStatus {}
record Checkmate(Player winner) implements GameStatus {}
record Stalemate() implements GameStatus {}
record Resignation(Player winner) implements GameStatus {}

// SOLID: SRP — move validation is separate from the central game coordinator

// Design Pattern: Facade — Provides a simple interface for clients to play the game,
// hiding the complex interactions between Board, Pieces, and Validators.
class ChessGame {
    private Board board;
    private Player[] players;
    private int currentTurn; // 0 for White, 1 for Black
    private GameStatus status;
    private MoveValidator validator;
    
    public ChessGame(Player p1, Player p2) {
        this.board = new Board();
        this.players = new Player[]{p1, p2};
        this.currentTurn = 0;
        this.status = new InProgress();
        this.validator = new StandardMoveValidator();
    }
    
    public boolean playMove(Position from, Position to) {
        if (!(status instanceof InProgress || status instanceof Check)) {
            System.out.println("Game is over.");
            return false;
        }
        
        Piece p = board.getPieceAt(from);
        if (p == null || p.getColor() != players[currentTurn].color) {
            return false; // Not your turn or empty square
        }
        
        if (validator.isValid(board, p, to)) {
            board.movePiece(p, to);
            updateGameStatus();
            currentTurn = 1 - currentTurn; // Swap turns
            return true;
        }
        return false;
    }

}

5. Why is it recommended / When to use it?

This object-oriented structure is highly extensible. By making Piece abstract and using Polymorphism, adding new fairy chess pieces or modifying movement rules becomes trivial. The use of a MoveValidator ensures the ChessGame class doesn't become a "God Class" filled with complex logic.

Interview Tip: Mention how you handle check validation. The typical approach is to simulate the proposed move on a cloned or scratchpad board and see if the king is under attack, before committing it to the actual game board.
