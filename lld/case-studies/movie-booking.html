Design a Movie Booking System (BookMyShow)

Scenario: Design a movie ticket booking system like BookMyShow where users can view available movies, select seats, and book tickets concurrently without race conditions.

1. What is a Movie Booking System?

A system handling theaters, screens, shows, and seats. Multiple users might try to book the same seat at the same time, necessitating a robust locking mechanism.

📖 Concurrency Control: Ensuring that when User A and User B try to book Seat #12 simultaneously, only one succeeds and the other gets an error gracefully.

2. What problem does it solve?

Handling temporary locks on seats during checkout so other users can't select them, and releasing them if the payment times out. It abstracts physical theater complexes into software entities.

3. How does it work?

4. Java 21 Code Implementation

Java 

import java.util.*;
import java.util.concurrent.*;
import java.time.LocalDateTime;

record MovieId(String id) {}
record Movie(MovieId id, String title, String genre, int durationMinutes, String rating) {}
record User(String id, String name) {}

enum SeatType { REGULAR, PREMIUM, VIP }
enum SeatStatus { AVAILABLE, LOCKED, BOOKED }

// SOLID: Single Responsibility — this class only handles seat properties
class Seat {
    String id; int row, number; SeatType type; SeatStatus status;
    public Seat(String id, int row, int number, SeatType type) {
        this.id = id; this.row = row; this.number = number; this.type = type; this.status = SeatStatus.AVAILABLE;
    }
}

class Screen {
    String screenNumber; List<Seat> seats;
    public Screen(String num, List<Seat> seats) { this.screenNumber = num; this.seats = seats; }
}

record Show(String showId, Movie movie, Screen screen, LocalDateTime startTime, Map<SeatType, Double> pricing) {}

class Theater {
    String name, address; List<Screen> screens;
}

record Booking(String bookingId, Show show, List<Seat> seats, User user, double totalAmount, LocalDateTime bookingTime) {}

// Key Differentiator for Concurrency
class SeatLockManager {
    // Stores ShowID_SeatID -> Lock Expiry Time
    private final ConcurrentHashMap<String, Long> locks = new ConcurrentHashMap<>();
    
    public synchronized boolean lockSeats(Show show, List<Seat> seats) {
        // Check if any seat is already locked or booked
        for (Seat s : seats) {
            if (s.status != SeatStatus.AVAILABLE) return false;
        }
        // Lock them
        long expiry = System.currentTimeMillis() + 60000; // 1 minute lock
        for (Seat s : seats) {
            s.status = SeatStatus.LOCKED;
            locks.put(show.showId() + "_" + s.id, expiry);
        }
        return true;
    }
}

// Design Pattern: Strategy — interchangeable algorithms for payment
interface PaymentStrategy {
    boolean pay(double amount);
}

class CreditCardPayment implements PaymentStrategy {
    public boolean pay(double amount) { System.out.println("Paid via Credit Card"); return true; }
}
class UpiPayment implements PaymentStrategy {
    public boolean pay(double amount) { System.out.println("Paid via UPI"); return true; }
}

// Design Pattern: Observer — notify subscribers on state change
interface BookingObserver {
    void onBookingConfirmed(Booking booking);
}

class EmailNotifier implements BookingObserver {
    public void onBookingConfirmed(Booking booking) { System.out.println("Email Sent for booking: " + booking.bookingId()); }
}

// Design Pattern: Facade
class BookingService {
    private SeatLockManager lockManager = new SeatLockManager();
    private List<BookingObserver> observers = new ArrayList<>();
    
    public void addObserver(BookingObserver obs) { observers.add(obs); }
    
    public Booking bookSeats(User user, Show show, List<Seat> seats, PaymentStrategy paymentMethod) {
        if (!lockManager.lockSeats(show, seats)) {
            throw new RuntimeException("Seats not available");
        }
        
        double amount = seats.stream().mapToDouble(s -> show.pricing().get(s.type)).sum();
        
        if (paymentMethod.pay(amount)) {
            seats.forEach(s -> s.status = SeatStatus.BOOKED);
            Booking b = new Booking(UUID.randomUUID().toString(), show, seats, user, amount, LocalDateTime.now());
            observers.forEach(o -> o.onBookingConfirmed(b));
            return b;
        }
        return null;
    }
}

public class Main {
    public static void main(String[] args) {
        BookingService service = new BookingService();
        service.addObserver(new EmailNotifier());
        
        // Setup mock data...
        Seat s1 = new Seat("S1", 1, 1, SeatType.REGULAR);
        Show show = new Show("SHOW1", new Movie(new MovieId("M1"), "Inception", "Sci-Fi", 120, "PG-13"), new Screen("Scr1", List.of(s1)), LocalDateTime.now(), Map.of(SeatType.REGULAR, 150.0));
        
        service.bookSeats(new User("U1", "Alice"), show, List.of(s1), new UpiPayment());
    }
}

5. Why is this recommended?

Using a dedicated SeatLockManager handles concurrency and isolates locking logic from the business workflow, respecting Single Responsibility Principle. The Strategy pattern for payments prevents a monolithic checkout method.

Interview Tip: Real-world booking systems use distributed caching like Redis for seat locking (using TTL - Time to Live) so the locks automatically expire across all servers without relying on a single machine's memory.
