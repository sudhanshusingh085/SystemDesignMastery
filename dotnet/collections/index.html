2. `List<T>` Internals: Capacity Doubling & Array.Copy

A C# List<T> is a dynamic wrapper around a contiguous native managed array (T[] _items):

  • Growth Algorithm: When the list exceeds its current capacity, it allocates a new array of 2x the current capacity (or 4 if empty) and copies existing elements using Array.Copy() (which uses vectorized memmove CPU instructions).
  • Capacity vs Count: Count is the number of active elements. Capacity is the length of the internal _items array.

⚠️ The Cost of `Insert(0, item)`

Inserting at index 0 has a time complexity of O(N). The runtime must shift all N existing elements right by one position in memory. If you require frequent prepending, use LinkedList<T> or a double-ended ring buffer.

3. `Dictionary<TKey, TValue>` Internals: The Prime Sizing Engine

📖 Internal Layout

Unlike Java's HashMap (which uses linked-list node objects on the heap), .NET's Dictionary<TKey, TValue> stores everything in two flat arrays to maximize CPU L1/L2 cache locality and eliminate GC node pressure.

The Two Backing Arrays

private struct Entry
{
    public uint hashCode; // 31-bit positive hash code (-1 if unused)
    public int next;      // Index of next entry in bucket chain (-1 if last)
    public TKey key;      // The Key
    public TValue value;  // The Value
}

private int[] _buckets;      // Array of indices into _entries
private Entry[] _entries;    // Array of Entry structs containing keys, values & chains

Why Does .NET Use Prime Numbers for Capacity?

In modular arithmetic, computing bucket = hashCode % capacity has a mathematical vulnerability: if capacity is a power of 2, the modulo operation only inspects the lowest bits of the hash code (e.g., hash & (capacity - 1)). If hash codes share common factors or alignment, they all collide into the same few buckets!

Using a prime number for the bucket array size guarantees that the hash code's full bit entropy is distributed evenly across all buckets, even if the user's hash function is mediocre. .NET maintains an internal static table of 72 prime numbers ranging from 3 up to 7,199,369.

Fast Modulo Optimization (.NET 6+)

Division and modulo operations on 64-bit CPUs take ~15-30 clock cycles. Modern .NET replaces division with fast multiplicative reduction (Lemire reduction):

// Instead of: bucketIndex = (uint)hashCode % (uint)buckets.Length;
// RyuJIT emits high-64-bit multiplication:
bucketIndex = (uint)((((ulong)hashCode) * ((ulong)buckets.Length)) >> 32);

4. `ConcurrentDictionary<TKey, TValue>`: Striped Locking

ConcurrentDictionary provides high-concurrency thread safety without locking the entire collection. It achieves this using Striped Locking:

flowchart TD Req1["Thread 1: Put('AAPL')"] --> Lock0["Lock Stripe 0"] Req2["Thread 2: Put('GOOG')"] --> Lock1["Lock Stripe 1"] Req3["Thread 3: Read('MSFT')"] --> LockFree["Lock-Free Read (Volatile)"] Lock0 --> Table0["Bucket Partition 0"] Lock1 --> Table1["Bucket Partition 1"]
  • Lock Striping: By default, it initializes Environment.ProcessorCount * 2 lock objects. Each lock protects a distinct subset of the bucket tables. Two threads writing to keys governed by different locks run completely in parallel!
  • Lock-Free Reads: Reading from a ConcurrentDictionary (via TryGetValue or indexer) takes zero locks. The runtime executes lock-free memory reads via volatile bucket pointer dereferencing.
🚨 The `GetOrAdd` Factory Trap

In ConcurrentDictionary, the valueFactory delegate passed to GetOrAdd or AddOrUpdate is executed outside the lock to prevent deadlocks. If 10 threads concurrently request a missing key, the factory delegate may be executed 10 times in parallel! If your factory performs expensive operations (e.g., calling an external REST API or database query), wrap the value in Lazy<T>:

// ❌ WRONG: Factory may execute 10 times concurrently!
var user = cache.GetOrAdd(userId, id => FetchUserFromSlowDatabase(id));

// ✅ RIGHT: Factory executes cheap Lazy creation; expensive work runs once!
var lazyCache = new ConcurrentDictionary<string, Lazy<Task<User>>>();

var user = await lazyCache.GetOrAdd(userId, id => 
    new Lazy<Task<User>>(() => FetchUserFromSlowDatabase(id))).Value;

5. .NET 8 Frozen Collections (`FrozenDictionary` & `FrozenSet`)

In enterprise microservices, many dictionaries are configured once during application startup (e.g. routing tables, tax calculators, country code lookups) and never modified again. Standard Dictionary incurs overhead because it must support future mutations.

FrozenDictionary<TKey, TValue> analyzes the exact set of keys at startup to synthesize an optimal, collision-free lookup strategy (e.g., perfect hashing, single-byte ASCII direct jumps):

using System.Collections.Frozen;

// Read-only reference table initialized once at boot
private static readonly FrozenDictionary<string, CurrencyRate> ExchangeRates =
    LoadRatesFromConfig().ToFrozenDictionary(StringComparer.OrdinalIgnoreCase);

public decimal ConvertUsd(string targetCurrency, decimal amount)
{
    // Up to 50% faster than standard Dictionary with 0 allocation overhead!
    return amount * ExchangeRates[targetCurrency].Rate;
}

6. The Senior Interviewer's Grill Round: Collections

🔥 Question 1: What happens if two different keys have the same hash code in Dictionary?

Senior Answer: When two keys produce identical hash codes (a hash collision), they map to the same bucket in _buckets. In .NET's Dictionary, collision resolution is handled via separate chaining within the _entries array: the new entry is appended to _entries, and its next field is set to point to the index of the previously mapped entry. When looking up a key, the runtime traverses the linked index chain (entry = _entries[entry.next]) and calls IEqualityComparer<TKey>.Equals(key1, key2) to identify the exact match.

🔥 Question 2: Why does modifying a List<T> during a foreach loop throw InvalidOperationException?

Senior Answer: List<T> contains an internal integer field called _version, which increments every time an element is added, removed, or the list is cleared. When a foreach loop starts, it creates a struct enumerator (List<T>.Enumerator) that snapshots the initial _version into a local field (_version = list._version). On every call to MoveNext(), the enumerator verifies whether _version == list._version. If any modification occurs during iteration, the versions mismatch, and it immediately throws an InvalidOperationException to prevent unpredictable state corruption (Fail-Fast behavior).

🔥 Question 3: How does PriorityQueue<TElement, TPriority> work internally?

Senior Answer: Introduced in .NET 6, PriorityQueue<TElement, TPriority> implements a 4-ary (quad) min-heap backed by an array of (TElement Element, TPriority Priority) tuples. Unlike a standard binary heap (which has 2 children per parent node), a 4-ary heap has 4 children per node. This makes the tree shallower and significantly improves CPU cache hit ratios during heap-up (Enqueue) and heap-down (Dequeue) operations.
