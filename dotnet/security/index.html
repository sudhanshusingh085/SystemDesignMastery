1. Hardening JWT Bearer Authentication in ASP.NET Core

JSON Web Tokens (JWT) are the standard bearer tokens for stateless microservices. However, misconfigured token validation parameters represent one of the most common security vulnerabilities in enterprise cloud environments.

Hardened JWT Configuration in Program.cs

using Microsoft.AspNetCore.Authentication.JwtBearer;
using Microsoft.IdentityModel.Tokens;

builder.Services.AddAuthentication(options =>
{
    options.DefaultAuthenticateScheme = JwtBearerDefaults.AuthenticationScheme;
    options.DefaultChallengeScheme = JwtBearerDefaults.AuthenticationScheme;
})
.AddJwtBearer(options =>
{
    options.Authority = "https://identity.enterprise.com";
    options.Audience = "trading-api";
    options.RequireHttpsMetadata = true;

    options.TokenValidationParameters = new TokenValidationParameters
    {
        ValidateIssuer = true,
        ValidIssuer = "https://identity.enterprise.com",

        ValidateAudience = true,
        ValidAudience = "trading-api",

        ValidateIssuerSigningKey = true,
        ValidateLifetime = true,

        // 🚨 CRITICAL: Default ClockSkew is 5 minutes!
        // An expired token remains valid for 5 additional minutes unless set to TimeSpan.Zero!
        ClockSkew = TimeSpan.Zero,

        RequireSignedTokens = true,
        RequireExpirationTime = true
    };
});

2. Policy-Based & Resource-Based Authorization

📖 Why Role-Based Security Fails at Scale

Hardcoding roles like [Authorize(Roles = "Manager")] creates brittle, inflexible code. If compliance introduces a new "Senior Trader" role with partial permissions, every controller in the enterprise must be modified. Policy-Based Authorization decouples permissions from user roles through requirements and handlers.

A. Custom Authorization Requirement & Handler

// 1. The Requirement (Declaration of intent)
public sealed class TradingLimitRequirement(decimal maxNotional) : IAuthorizationRequirement
{
    public decimal MaxNotional { get; } = maxNotional;
}

// 2. The Handler (Evaluates rules against ClaimsPrincipal)
public sealed class TradingLimitHandler : AuthorizationHandler<TradingLimitRequirement>
{
    protected override Task HandleRequirementAsync(
        AuthorizationHandlerContext context, 
        TradingLimitRequirement requirement)
    {
        var limitClaim = context.User.FindFirst("TraderLimit")?.Value;

        if (decimal.TryParse(limitClaim, out var userLimit) && userLimit >= requirement.MaxNotional)
        {
            context.Succeed(requirement);
        }

        return Task.CompletedTask;
    }
}

// 3. Registering the policy in Program.cs:
builder.Services.AddAuthorization(options =>
{
    options.AddPolicy("ExecutiveTraderOnly", policy =>
        policy.Requirements.Add(new TradingLimitRequirement(10_000_000m)));
});

B. Resource-Based Authorization

When authorization depends on the specific database entity being accessed (e.g. "Can this user cancel Order #4812?"), use IAuthorizationService imperatively inside the handler:

public sealed class OrderCancellationHandler : AuthorizationHandler<OperationAuthorizationRequirement, Order>
{
    protected override Task HandleRequirementAsync(
        AuthorizationHandlerContext context,
        OperationAuthorizationRequirement requirement,
        Order order)
    {
        var userId = context.User.FindFirst(ClaimTypes.NameIdentifier)?.Value;

        // User can only cancel their own order, unless they possess the Compliance Officer role
        if (order.OwnerId == userId || context.User.IsInRole("ComplianceOfficer"))
        {
            context.Succeed(requirement);
        }

        return Task.CompletedTask;
    }
}

3. Timing Side-Channel Attacks & Constant-Time Comparisons

🚨 The Timing Side-Channel Vulnerability

Standard string and byte array comparisons (==, SequenceEqual()) short-circuit on the very first mismatched byte. An attacker measuring HTTP response latency down to nanoseconds can deduce secret API keys or HMAC signatures byte-by-byte! If the first byte is correct, the response takes 10ns longer; if the first two bytes are correct, it takes 20ns longer.

Defeating Timing Attacks with `CryptographicOperations.FixedTimeEquals`

.NET provides hardware-assisted constant-time comparisons that inspect all bytes regardless of mismatches:

using System.Security.Cryptography;
using System.Text;

public static bool ValidateWebhookSignature(string payload, string incomingSignature, byte[] secretKey)
{
    using var hmac = new HMACSHA256(secretKey);
    byte[] computedHash = hmac.ComputeHash(Encoding.UTF8.GetBytes(payload));
    byte[] incomingHash = Convert.FromHexString(incomingSignature);

    // ❌ VULNERABLE TO TIMING ATTACKS:
    // return computedHash.SequenceEqual(incomingHash);

    // ✅ IMMUNE TO TIMING ATTACKS: Constant-time byte comparison!
    return CryptographicOperations.FixedTimeEquals(computedHash, incomingHash);
}

4. ASP.NET Core Data Protection API (DPAPI)

The ASP.NET Core Data Protection system encrypts sensitive data (session cookies, OAuth tokens, anti-forgery tokens) at rest with automatic key rotation and master cryptographic key management:

(Trader Session / Token)"] --> Protector["IDataProtector.Protect()"] Protector --> KeyRing["Cryptographic Key Ring
(Rotated every 90 days)"] KeyRing --> MasterKey["Master Encryption Key
(Azure Key Vault / AWS KMS)"] MasterKey --> Ciphertext["Cryptographically Encrypted Payload
'CfDJ8N...v8='"] 
using Microsoft.AspNetCore.DataProtection;

// Registering Data Protection with Distributed Redis Key Storage in Cloud Pods:
builder.Services.AddDataProtection()
    .SetApplicationName("TradingPlatform")
    .PersistKeysToStackExchangeRedis(redisConnection, "DataProtection-Keys")
    .ProtectKeysWithCertificate(encryptionCert);

// Consuming IDataProtector:
public class SensitiveTokenService(IDataProtectionProvider provider)
{
    private readonly IDataProtector _protector = provider.CreateProtector("UserSecretTokens.v1");

    public string EncryptSecret(string secret) => _protector.Protect(secret);
    public string DecryptSecret(string cipher) => _protector.Unprotect(cipher);
}

5. The Senior Interviewer's Grill Round: .NET Security

🔥 Question 1: How do you handle JWT revocation in a stateless microservice architecture?

Senior Answer: Because JWTs are cryptographically self-contained, they cannot be natively revoked before expiration without checking an external source. The industry standard pattern is:

  1. Short-Lived Access Tokens: Set access token lifespan to 5-15 minutes, paired with long-lived Refresh Tokens stored in the database.
  2. Distributed Blacklist (Deny-list): When a user logs out or changes their password, push their unique token ID (jti claim) or user ID into a high-speed Redis distributed cache with a TTL equal to the remaining token lifetime.
  3. Middleware Inspection: Fast middleware or custom JwtBearerEvents.OnTokenValidated checks Redis for the jti in under 0.5ms.

🔥 Question 2: Why should you never use SHA256 or MD5 for password storage, and what should you use in .NET?

Senior Answer: SHA256 and MD5 are cryptographic digest algorithms designed for maximum speed. Modern GPU clusters can compute billions of SHA256 hashes per second, making rainbow table and brute-force attacks trivial. Passwords must be hashed using a computationally and memory-intensive Key Derivation Function (KDF). In modern .NET, use Argon2id or PBKDF2 with 600,000+ iterations via Rfc2898DeriveBytes.Pbkdf2 or the built-in IPasswordHasher<TUser>.

🔥 Question 3: What happens to Data Protection if you run multiple load-balanced web pods without shared key storage?

Senior Answer: By default, ASP.NET Core stores Data Protection keys in local directory storage (e.g. %LOCALAPPDATA%\ASP.NET\DataProtection-Keys). If you run multiple web pods behind a load balancer without shared storage, Pod A will generate Key Ring A and Pod B will generate Key Ring B. When Pod A creates an authentication cookie or antiforgery token, and the client's next request is routed to Pod B, Pod B cannot decrypt the token and immediately logs the user out or throws a 400 Bad Request error. Production clusters must persist keys to a shared store like Redis, Azure Blob Storage, or SQL Server.
