Concurrency — Threads, Locks, and Parallel Execution

💡 What to expect: This guide covers everything from basic threads to Java 21 Virtual Threads, complete with real-world analogies, code, and common pitfalls.

1. What is Concurrency?

📖 Concurrency: The ability of a system to deal with multiple things at once (not necessarily doing them at the exact same time).

Analogy: Imagine one chef in a kitchen. They start boiling water for pasta, then while waiting, they chop vegetables, and then check the sauce. They are dealing with multiple dishes, even though they only have two hands and can only actively work on one thing at a specific millisecond.

📖 Parallelism: Doing multiple things at the exact same time.

Analogy: Imagine three chefs in the kitchen. One chef is boiling water, another is chopping vegetables, and the third is making the sauce. They are doing things at the exact same time.

2. Threads

📖 Thread: The smallest unit of processing that can be performed in an OS. It is a path of execution within a program.

Creating Threads in Java

Java 21 
// 1. Extending Thread class
class MyThread extends Thread {
    @Override
    public void run() {
        System.out.println("Thread running: " + Thread.currentThread().getName());
    }
}

// 2. Implementing Runnable
class MyRunnable implements Runnable {
    @Override
    public void run() {
        System.out.println("Runnable running: " + Thread.currentThread().getName());
    }
}

public class ThreadExample {
    public static void main(String[] args) {
        // Method 1
        MyThread t1 = new MyThread();
        t1.start();
        
        // Method 2
        Thread t2 = new Thread(new MyRunnable());
        t2.start();
        
        // Method 3 (Lambda - Modern approach)
        Thread t3 = new Thread(() -> {
            System.out.println("Lambda running: " + Thread.currentThread().getName());
        });
        t3.start();
    }
}

3. Race Condition

📖 Race Condition: Occurs when two or more threads can access shared data and they try to change it at the same time.

Analogy: Two people editing the same sentence in a Google Doc at the same time. One person types "Cat", the other types "Dog", and the final result is a mess like "CDaotg".

Java 21 
public class RaceConditionExample {
    private static int counter = 0;

    public static void main(String[] args) throws InterruptedException {
        Runnable incrementTask = () -> {
            for (int i = 0; i < 10000; i++) {
                counter++; // Not atomic! Actually 3 steps: read, increment, write
            }
        };

        Thread t1 = new Thread(incrementTask);
        Thread t2 = new Thread(incrementTask);

        t1.start();
        t2.start();

        t1.join();
        t2.join();

        // Expectation: 20000
        // Reality: 15342 (or some random number less than 20000)
        System.out.println("Final counter: " + counter); 
    }
}

4. synchronized / Locks

To fix race conditions, we need to ensure only one thread can access the critical section at a time.

Analogy: A bathroom lock. Only one person can be in the bathroom. Others must wait outside until the key is returned.

Java 21 
import java.util.concurrent.locks.ReentrantLock;

public class LockExamples {
    private int counter1 = 0;
    private int counter2 = 0;
    private int counter3 = 0;
    private final Object lock = new Object();
    private final ReentrantLock reentrantLock = new ReentrantLock();

    // 1. Synchronized Method (Locks the whole instance)
    public synchronized void increment1() {
        counter1++;
    }

    // 2. Synchronized Block (More granular)
    public void increment2() {
        synchronized(lock) {
            counter2++;
        }
    }

    // 3. ReentrantLock (More flexible)
    public void increment3() {
        reentrantLock.lock();
        try {
            counter3++;
        } finally {
            reentrantLock.unlock(); // ALWAYS unlock in a finally block
        }
    }
}

Lock vs Synchronized

FeaturesynchronizedReentrantLock
FlexibilityLow (block scoped)High (can lock/unlock in different methods)
Try-LockNoYes (tryLock())
FairnessNoYes (can be fair)

5. Deadlock

📖 Deadlock: When two or more threads are blocked forever, waiting for each other to release a lock.

Analogy: Two people walking towards each other in a narrow hallway. Person A steps to the right, Person B steps to the left (their right). They are both blocked, waiting for the other to move.

Java 21 
public class DeadlockExample {
    private static final Object lock1 = new Object();
    private static final Object lock2 = new Object();

    public static void main(String[] args) {
        Thread t1 = new Thread(() -> {
            synchronized (lock1) {
                System.out.println("Thread 1: Holding lock 1...");
                try { Thread.sleep(100); } catch (InterruptedException e) {}
                System.out.println("Thread 1: Waiting for lock 2...");
                synchronized (lock2) {
                    System.out.println("Thread 1: Holding lock 1 & 2...");
                }
            }
        });

        Thread t2 = new Thread(() -> {
            synchronized (lock2) { // To fix deadlock, acquire lock1 here instead!
                System.out.println("Thread 2: Holding lock 2...");
                try { Thread.sleep(100); } catch (InterruptedException e) {}
                System.out.println("Thread 2: Waiting for lock 1...");
                synchronized (lock1) {
                    System.out.println("Thread 2: Holding lock 1 & 2...");
                }
            }
        });

        t1.start();
        t2.start();
    }
}

6. Semaphore

📖 Semaphore: Maintains a set of permits. It restricts the number of threads that can access a resource.

Analogy: A parking lot with 5 spots. If 5 cars are in, the 6th car must wait at the gate until a car leaves and returns the ticket (permit).

Java 21 
import java.util.concurrent.Semaphore;

public class SemaphoreExample {
    // Only 3 threads can access the resource at the same time
    private static final Semaphore semaphore = new Semaphore(3);

    public static void accessResource(int threadId) {
        try {
            semaphore.acquire();
            System.out.println("Thread " + threadId + " acquired permit. Available: " + semaphore.availablePermits());
            Thread.sleep(2000); // Simulate work
        } catch (InterruptedException e) {
            e.printStackTrace();
        } finally {
            System.out.println("Thread " + threadId + " releasing permit.");
            semaphore.release();
        }
    }

    public static void main(String[] args) {
        for (int i = 1; i <= 6; i++) {
            final int id = i;
            new Thread(() -> accessResource(id)).start();
        }
    }
}

7. Thread Pool / ExecutorService

Creating threads is expensive. Instead of creating a new thread for every task, we use a pool of worker threads.

Java 21 
import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;

public class ThreadPoolExample {
    public static void main(String[] args) {
        // Create a pool of 3 fixed threads
        try (ExecutorService executor = Executors.newFixedThreadPool(3)) {
            
            for (int i = 1; i <= 10; i++) {
                final int taskId = i;
                executor.submit(() -> {
                    System.out.println("Task " + taskId + " running on " + Thread.currentThread().getName());
                });
            }
        } // ExecutorService implements AutoCloseable in modern Java, so it shuts down automatically here
    }
}

8. CompletableFuture

Modern Java's way of handling asynchronous programming. It allows chaining operations without blocking.

Java 21 
import java.util.concurrent.CompletableFuture;

public class CompletableFutureExample {
    public static void main(String[] args) {
        CompletableFuture<String> future = CompletableFuture.supplyAsync(() -> {
            // Simulate network call
            try { Thread.sleep(1000); } catch (InterruptedException e) {}
            return "User123";
        }).thenApply(user -> {
            // Transform data
            return user.toUpperCase();
        }).exceptionally(ex -> {
            // Handle errors
            System.out.println("Error: " + ex.getMessage());
            return "UNKNOWN";
        });

        // Non-blocking, main thread continues...
        
        // Wait for result for demonstration
        System.out.println("Result: " + future.join());
    }
}

9. Virtual Threads (Java 21)

📖 Virtual Threads: Lightweight threads introduced in Java 21 (Project Loom). They reduce the effort of writing, maintaining, and observing high-throughput concurrent applications.

Game Changer: You can create millions of virtual threads. They are not tied 1:1 to OS threads. Blocking a virtual thread (e.g., waiting for DB) does NOT block the OS thread.

Java 21 
import java.util.concurrent.Executors;

public class VirtualThreadsExample {
    public static void main(String[] args) {
        // Creating a single virtual thread
        Thread vThread = Thread.ofVirtual().start(() -> {
            System.out.println("Hello from Virtual Thread! " + Thread.currentThread());
        });

        // Using ExecutorService with Virtual Threads
        try (var executor = Executors.newVirtualThreadPerTaskExecutor()) {
            for (int i = 0; i < 100_000; i++) { // 100,000 threads! No problem.
                final int taskId = i;
                executor.submit(() -> {
                    try {
                        Thread.sleep(1000); // Does NOT block OS thread
                    } catch (InterruptedException e) {}
                });
            }
        }
    }
}

10. Concurrent Collections

Standard collections (ArrayList, HashMap) are not thread-safe. Java provides thread-safe alternatives in java.util.concurrent.

Java 21 
import java.util.concurrent.BlockingQueue;
import java.util.concurrent.LinkedBlockingQueue;

public class ProducerConsumerExample {
    public static void main(String[] args) {
        // Thread-safe queue
        BlockingQueue<String> queue = new LinkedBlockingQueue<>(5);

        Thread producer = new Thread(() -> {
            try {
                for (int i = 0; i < 10; i++) {
                    queue.put("Item " + i); // Blocks if queue is full
                    System.out.println("Produced: Item " + i);
                }
            } catch (InterruptedException e) {}
        });

        Thread consumer = new Thread(() -> {
            try {
                for (int i = 0; i < 10; i++) {
                    String item = queue.take(); // Blocks if queue is empty
                    System.out.println("Consumed: " + item);
                }
            } catch (InterruptedException e) {}
        });

        producer.start();
        consumer.start();
    }
}

11. Atomic Variables

Classes like AtomicInteger use Compare-And-Swap (CAS) instructions to be thread-safe without using locks. This is much faster than synchronized for simple counters.

Java 21 
import java.util.concurrent.atomic.AtomicInteger;

public class AtomicExample {
    private static AtomicInteger atomicCounter = new AtomicInteger(0);

    public static void main(String[] args) throws InterruptedException {
        Runnable task = () -> {
            for (int i = 0; i < 10000; i++) {
                atomicCounter.incrementAndGet(); // Thread-safe and fast!
            }
        };

        Thread t1 = new Thread(task);
        Thread t2 = new Thread(task);

        t1.start(); t2.start();
        t1.join(); t2.join();

        System.out.println("Result: " + atomicCounter.get()); // Exactly 20000
    }
}

🎯 Interview Tip: Interviewers love asking about deadlocks and how to prevent them. Always remember the simplest fix for a deadlock: ensure all threads acquire locks in the same global order. Also, mention Java 21 Virtual Threads as a modern solution for scaling I/O bound applications!
