Reliability & Fault Tolerance — Building Systems That Don't Break

1. What is Reliability?
Reliability means that a system continues to work correctly, even when parts of it fail.

Real-World Analogy: An airplane has backup engines. If one engine fails mid-flight, the plane doesn't crash; the backup engine takes over, allowing the plane to land safely.

2. Circuit Breaker Pattern

The Circuit Breaker pattern prevents a system from repeatedly trying to execute an operation that's likely to fail. It stops calling a failing service to give it time to recover.

Real-World Analogy: An electrical circuit breaker in your house cuts the power when there's an overload to prevent a fire.

Figure 1: Circuit Breaker States

public class CircuitBreakerDemo {
    sealed interface State permits Closed, Open, HalfOpen {}
    record Closed() implements State {}
    record Open(long openedAt) implements State {}
    record HalfOpen() implements State {}

    public static class CircuitBreaker {
        private State state = new Closed();
        private int failureCount = 0;
        private final int threshold = 3;
        private final long timeoutMs = 5000;

        public void recordFailure() {
            if (state instanceof Closed) {
                failureCount++;
                if (failureCount >= threshold) {
                    state = new Open(System.currentTimeMillis());
                }
            } else if (state instanceof HalfOpen) {
                state = new Open(System.currentTimeMillis());
            }
        }

        public boolean allowRequest() {
            return switch (state) {
                case Closed c -> true;
                case Open o -> {
                    if (System.currentTimeMillis() - o.openedAt() > timeoutMs) {
                        state = new HalfOpen();
                        yield true;
                    }
                    yield false;
                }
                case HalfOpen h -> true;
            };
        }
    }
}
public abstract record CircuitState
{
    public sealed record Closed : CircuitState;
    public sealed record Open(DateTime OpenedAtUtc) : CircuitState;
    public sealed record HalfOpen : CircuitState;
}

public class CircuitBreaker(int threshold = 3, TimeSpan timeout = default)
{
    private CircuitState _state = new CircuitState.Closed();
    private int _failureCount;
    private readonly TimeSpan _timeout = timeout == default ? TimeSpan.FromSeconds(5) : timeout;
    private readonly object _lock = new();

    public void RecordFailure()
    {
        lock (_lock)
        {
            if (_state is CircuitState.Closed)
            {
                if (++_failureCount >= threshold)
                    _state = new CircuitState.Open(DateTime.UtcNow);
            }
            else if (_state is CircuitState.HalfOpen)
            {
                _state = new CircuitState.Open(DateTime.UtcNow);
            }
        }
    }

    public bool AllowRequest()
    {
        lock (_lock)
        {
            return _state switch
            {
                CircuitState.Closed => true,
                CircuitState.Open o when DateTime.UtcNow - o.OpenedAtUtc > _timeout =>
                    (_state = new CircuitState.HalfOpen()) is not null,
                CircuitState.Open => false,
                CircuitState.HalfOpen => true,
                _ => false
            };
        }
    }
}

3. Retry with Exponential Backoff

If a request fails temporarily, try again. But instead of hammering the system, wait longer between each retry (exponential backoff) and add randomness (jitter) to prevent thundering herd problems.

import java.util.concurrent.ThreadLocalRandom;

public class RetryHandler {
    private final int maxRetries = 3;
    private final long initialDelayMs = 100;
    private final double multiplier = 2.0;
    
    public void executeWithRetry(Runnable action) {
        int attempt = 0;
        long delay = initialDelayMs;
        
        while (attempt < maxRetries) {
            try {
                action.run();
                return;
            } catch (Exception e) {
                attempt++;
                if (attempt == maxRetries) throw e;
                long jitter = ThreadLocalRandom.current().nextLong(delay / 2);
                try { Thread.sleep(delay + jitter); } catch (InterruptedException ie) { Thread.currentThread().interrupt(); }
                delay *= multiplier;
            }
        }
    }
}
public class RetryHandler(int maxRetries = 3, int initialDelayMs = 100, double multiplier = 2.0)
{
    public async Task ExecuteWithRetryAsync(Func<Task> action, CancellationToken ct = default)
    {
        int attempt = 0;
        double delayMs = initialDelayMs;

        while (attempt < maxRetries)
        {
            try
            {
                await action();
                return; // Success
            }
            catch (Exception) when (++attempt < maxRetries)
            {
                // Full jitter pattern to avoid thundering herds
                int jitterMs = Random.Shared.Next(0, (int)(delayMs / 2));
                await Task.Delay(TimeSpan.FromMilliseconds(delayMs + jitterMs), ct);
                delayMs *= multiplier;
            }
        }
    }
}

4. Timeout

Never wait forever for a response. If a service is hanging, it can lock up your threads.

Real-World Analogy: A restaurant customer leaves if they've been waiting for their food for over an hour.

import java.util.concurrent.CompletableFuture;
import java.util.concurrent.TimeUnit;

public class TimeoutWrapper {
    public void executeWithTimeout() {
        CompletableFuture<String> future = CompletableFuture.supplyAsync(() -> {
            return "Result";
        });
        
        future.orTimeout(2, TimeUnit.SECONDS)
              .exceptionally(ex -> {
                  System.out.println("Operation timed out!");
                  return "Fallback Response";
              });
    }
}
public class TimeoutWrapper
{
    public static async Task<string> ExecuteWithTimeoutAsync(Func<CancellationToken, Task<string>> operation)
    {
        using var cts = new CancellationTokenSource(TimeSpan.FromSeconds(2));
        try
        {
            // .NET 8 Task.WaitAsync with timeout cancellation token
            return await operation(cts.Token).WaitAsync(TimeSpan.FromSeconds(2), cts.Token);
        }
        catch (TimeoutException)
        {
            Console.WriteLine("Operation timed out! Falling back to cache/default.");
            return "Fallback Response (.NET 8)";
        }
    }
}

5. Bulkhead Pattern

Isolate different parts of your application so a failure in one area doesn't cascade and take down the entire system.

Real-World Analogy: Ship compartments. If the hull is breached in one compartment, water doesn't flood the whole ship.

import java.util.concurrent.Semaphore;

public class BulkheadExecutor {
    // Only allow 5 concurrent requests to Payment Service
    private final Semaphore paymentBulkhead = new Semaphore(5);
    
    public void processPayment(Runnable task) {
        if (paymentBulkhead.tryAcquire()) {
            try {
                task.run();
            } finally {
                paymentBulkhead.release();
            }
        } else {
            throw new RuntimeException("Payment service is too busy!");
        }
    }
}
public class BulkheadExecutor(int maxConcurrency = 5)
{
    private readonly SemaphoreSlim _semaphore = new(maxConcurrency, maxConcurrency);

    public async Task ProcessPaymentAsync(Func<Task> task)
    {
        // Non-blocking async check: reject immediately if capacity saturated
        if (await _semaphore.WaitAsync(TimeSpan.Zero))
        {
            try
            {
                await task();
            }
            finally
            {
                _semaphore.Release();
            }
        }
        else
        {
            throw new InvalidOperationException("Payment bulkhead limit reached! Fast failure applied.");
        }
    }
}

8. Health Checks

Load balancers need to know if a server is alive before sending it traffic.

import java.util.List;

public class HealthCheckDemo {
    interface HealthCheck {
        boolean isHealthy();
    }
    
    record DatabaseHealthCheck() implements HealthCheck {
        public boolean isHealthy() { return true; /* ping DB */ }
    }
    
    record CompositeHealthCheck(List<HealthCheck> checks) implements HealthCheck {
        public boolean isHealthy() {
            return checks.stream().allMatch(HealthCheck::isHealthy);
        }
    }
}
public interface IHealthCheck
{
    ValueTask<bool> CheckHealthAsync(CancellationToken ct = default);
}

public sealed record DatabaseHealthCheck : IHealthCheck
{
    public ValueTask<bool> CheckHealthAsync(CancellationToken ct = default) =>
        ValueTask.FromResult(true); // Pings database connection
}

public sealed class CompositeHealthCheck(IEnumerable<IHealthCheck> checks) : IHealthCheck
{
    public async ValueTask<bool> CheckHealthAsync(CancellationToken ct = default)
    {
        var results = await Task.WhenAll(checks.Select(c => c.CheckHealthAsync(ct).AsTask()));
        return results.All(r => r);
    }
}

9. Graceful Degradation

If a non-critical feature fails, return a partial result instead of crashing the whole page.

Real-World Analogy: Netflix might show you cached, generic movie recommendations if their personalized recommendation service goes down, rather than showing a blank screen.

10. Chaos Engineering

Intentionally breaking things in production to test resilience. Best example: Netflix Chaos Monkey, which randomly terminates EC2 instances to ensure the system survives.
