API Design — Building Clean, Production-Grade APIs

Interview Tip: "Design the API for X" is a common interview question. Mastering these conventions will show your interviewer you understand how to build real-world, production-ready systems.

1. What is an API?

An

📖 API (Application Programming Interface): A set of rules and protocols that allows different software applications to communicate with each other.
is like a restaurant menu.

Imagine you're at a restaurant. You (the client) look at the menu (the API) which lists available dishes. You place an order with the waiter (the network). The waiter takes the order to the kitchen (the server), where the chefs prepare it. Finally, the waiter brings your food (the response) back to you. You don't need to know how the kitchen cooked it, just what to ask for!

In modern systems, we typically build

📖 REST (Representational State Transfer): An architectural style for designing networked applications, relying on a stateless, client-server protocol, usually HTTP.
APIs.

2. RESTful Conventions

RESTful APIs are designed around resources. A resource is an object or representation of something, like a user, a tweet, or a product.

  • Use nouns for URLs, not verbs: /users, not /getUsers
  • Use plural nouns: /users, /orders
  • Identify specific resources by ID: /users/123

HTTP Methods map to CRUD operations:

4. Request/Response Design

An envelope pattern wraps all responses in a standard structure. This makes it easier for clients to parse results and errors consistently.

Java 21 
public sealed interface ApiResponse<T> permits ApiResponse.Success, ApiResponse.Error {
    
    // Success record holds the payload
    record Success<T>(T data, String message) implements ApiResponse<T> {}
    
    // Error record holds details about the failure
    record Error<T>(String code, String message, List<String> details) implements ApiResponse<T> {}

    static <T> ApiResponse<T> success(T data) {
        return new Success<>(data, "Operation successful");
    }

    static <T> ApiResponse<T> error(String code, String message) {
        return new Error<>(code, message, List.of());
    }
}

With Java 21's pattern matching, handling responses is very clean:

Java 21 
void handleResponse(ApiResponse<User> response) {
    switch (response) {
        case ApiResponse.Success<User> s -> System.out.println("Got user: " + s.data().name());
        case ApiResponse.Error<User> e -> System.err.println("Failed: " + e.message());
    }
}

5. Pagination

When returning lists, you can't return millions of items at once. You must paginate.

Offset-based Pagination

Uses page and size (or limit and offset).

Example: /users?page=2&size=10

Pros: Easy to implement, can jump to a specific page.

Cons: Slower on large tables, data can shift if items are added/deleted while paginating.

Cursor-based Pagination

Uses a cursor pointing to the last seen item.

Example: /users?cursor=xyz123&limit=10

Pros: Fast regardless of size, data doesn't shift.

Cons: Harder to implement, cannot jump to page 10 directly.

Java 21 
// Offset-based request and response
public record PageRequest(int page, int size) {}
public record PageResponse<T>(List<T> items, int totalPages, long totalElements) {}

// Cursor-based request and response
public record CursorRequest(String cursor, int limit) {}
public record CursorPageResponse<T>(List<T> items, String nextCursor, boolean hasMore) {}

6. Filtering, Sorting, Searching

Use query parameters for operations that narrow down collections.

  • Filtering: /users?role=admin&status=active
  • Sorting: /users?sort=createdAt:desc
  • Searching: /users?q=john

8. Idempotency

📖 Idempotency: An operation is idempotent if doing it once has the same effect as doing it multiple times.

Crucial for payment APIs. If a network drops during a POST, the client retries. An idempotency key ensures the payment isn't processed twice.

Java 21 
public class IdempotencyFilter {
    private final Set<String> processedKeys = ConcurrentHashMap.newKeySet();

    public void processPayment(String idempotencyKey, PaymentRequest request) {
        if (processedKeys.contains(idempotencyKey)) {
            System.out.println("Payment already processed. Returning cached response.");
            return;
        }
        // Process payment
        processedKeys.add(idempotencyKey);
        System.out.println("Payment processed successfully.");
    }
}

9. Rate Limiting Headers

Protect APIs from abuse using rate limits. Good APIs return these headers:

  • X-RateLimit-Limit: Total allowed requests in a window.
  • X-RateLimit-Remaining: Remaining requests.
  • Retry-After: Seconds to wait before retrying (when you get a 429).

11. API Documentation

Tools like OpenAPI (Swagger) allow you to define your API structure. It auto-generates interactive documentation and even client SDKs.

12. Common Mistakes

  • Using verbs in URLs (e.g. /createUser instead of POST /users).
  • Inconsistent naming conventions (mixing camelCase and snake_case).
  • Not paginating large collections, causing server memory exhaustion.
  • Ignoring API versioning from the start.
