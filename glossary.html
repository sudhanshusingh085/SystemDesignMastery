Technical Glossary

Welcome to the System Design Mastery Glossary. This page contains simple, beginner-friendly definitions of technical terms used throughout the site, complete with real-world analogies.

A

Abstract Class
A class that cannot be instantiated on its own and is meant to be subclassed by other classes. It provides a common template or base structure.
Analogy: Think of it as a blueprint for a "Vehicle". You can't build a generic "Vehicle", you must build a specific "Car" or "Truck" that follows the blueprint.
Read more
API (Application Programming Interface)
A set of rules that lets different software programs communicate with each other.
Analogy: Like a waiter in a restaurant. You (the client) tell the waiter your order (request), the waiter goes to the kitchen (server), and brings you back your food (response).
Read more
API Gateway
A server that acts as a front door for all requests coming into a system, routing them to the correct microservice.
Analogy: A receptionist at a large corporate building who directs visitors to the correct department.
Read more
Abstraction
Hiding complex implementation details and showing only the essential features of an object.
Analogy: Driving a car. You know how to use the steering wheel and pedals (the abstraction) without needing to understand how the internal combustion engine works.
Read more
ACID
Atomicity, Consistency, Isolation, Durability. A set of properties that guarantee database transactions are processed reliably.
Analogy: A bank transfer. The money must leave your account AND arrive in the recipient's account (Atomic). It shouldn't leave the system in a broken state (Consistent). No one should see the transfer half-finished (Isolated), and once done, it's permanent (Durable).
Read more
Asynchronous
A programming pattern where a task is started and the system continues to do other things while waiting for it to finish, rather than pausing entirely.
Analogy: Ordering food delivery. You place the order (start task), then watch TV while you wait (continue other work), instead of standing by the door doing nothing until the food arrives (synchronous).
Read more
Authentication
The process of verifying who a user is.
Analogy: Showing your ID at a security checkpoint.
Read more
Authorization
The process of verifying what a specific user is allowed to do.
Analogy: Having a VIP pass. Authentication gets you in the door; authorization determines if you can enter the VIP lounge.
Read more
Auto-scaling
Automatically adjusting the number of computing resources (servers) based on current traffic.
Analogy: A supermarket opening more checkout lanes when the lines get long, and closing them when the store is empty.
Read more
Availability
The percentage of time a system is fully operational and accessible.
Analogy: A 24/7 convenience store has higher availability than a bank that's only open 9 to 5.
Read more

B

Backend
The part of a software application that runs on the server, hidden from the user, handling data storage, business logic, and security.
Analogy: The kitchen and storage rooms of a restaurant where the actual cooking happens.
Read more
Bandwidth
The maximum rate of data transfer across a given path in a network.
Analogy: The width of a highway. A wider highway (more bandwidth) allows more cars (data) to travel at once.
Read more
Base62
A numeral system that uses 62 characters (0-9, a-z, A-Z) to represent numbers, often used to create short URLs.
Analogy: Using a much larger alphabet so you can spell very big numbers using very few characters.
Read more
Blocking Queue
A queue that blocks a thread attempting to take an item from it if the queue is empty, and blocks a thread attempting to add an item if the queue is full.
Analogy: A factory conveyor belt. Workers block (wait) if there are no parts to assemble, and block (stop putting things on) if the belt is completely full.
Read more
Builder Pattern
A design pattern that lets you construct complex objects step by step.
Analogy: Ordering a custom sandwich at Subway. You specify the bread, meat, cheese, and veggies step-by-step to build your final sandwich.
Read more
Byte
A unit of digital data that typically consists of eight bits.
Analogy: A single character in a book. It's a small, fundamental building block of information.
Read more

C

Cache
A temporary, fast storage layer that keeps a copy of frequently accessed data so it can be retrieved much quicker than fetching it from the main database.
Analogy: Keeping your most frequently used spices on the kitchen counter instead of digging through the pantry every time.
Read more
Cache Eviction
The process of removing old or less useful data from a cache to make room for new data.
Analogy: Throwing out old leftovers from a full fridge so you have space for tonight's groceries.
Read more
Cache Hit / Miss
A "Hit" is when requested data is found in the cache. A "Miss" is when it isn't, requiring a slow fetch from the main database.
Analogy: Looking for your keys in your pocket. If they are there, it's a hit. If not, you have to search the whole house (a miss).
Read more
CAP Theorem
A principle stating that a distributed database can only guarantee two out of three: Consistency, Availability, and Partition Tolerance.
Analogy: "Fast, cheap, or good: pick two." But for databases in a network.
Read more
CDN (Content Delivery Network)
A geographically distributed group of servers that work together to provide fast delivery of Internet content (images, videos, HTML pages).
Analogy: Amazon opening local warehouses all over the country so packages arrive faster, instead of shipping everything from one central factory.
Read more
Client
A computer hardware device or software program that accesses a service made available by a server.
Analogy: The customer in a restaurant ordering food from the waiter.
Read more
Concurrency
The ability of a system to execute multiple parts of a program simultaneously or interleaved.
Analogy: A chef cooking soup, roasting a chicken, and chopping veggies at the same time by switching between tasks.
Read more
Consistency
Ensuring that every read from a database receives the most recent write.
Analogy: If you update your bank balance at an ATM, checking your balance on your phone 1 second later should show the exact same number.
Read more
Consistent Hashing
A technique used in distributed systems to distribute data evenly across servers while minimizing reorganization when servers are added or removed.
Analogy: Assigning mailmen to delivery routes based on a circular map so that if one mailman gets sick, only their immediate neighbor has to take over their route, rather than reorganizing all routes.
Read more
CRUD
Create, Read, Update, Delete — the four basic operations of persistent storage.
Analogy: Interacting with a notebook. You can write a new page (Create), read a page (Read), erase and rewrite a line (Update), or tear out a page (Delete).
Read more
Constructor
A special method in a class that is automatically called when an object of that class is created.
Analogy: The factory assembly line process that initially builds and paints a car as soon as it's ordered.
Read more

D

Database
An organized collection of data, generally stored and accessed electronically from a computer system.
Analogy: A massive digital filing cabinet where information is perfectly organized so you can find anything instantly.
Read more
Docker
A platform for developing, shipping, and running applications in isolated containers.
Analogy: Shipping containers. Standardized boxes that can carry any kind of goods and fit on any ship, train, or truck without modifying the cargo.
Read more

H

HTTP / HTTPS
The foundation of data communication for the World Wide Web. HTTPS is the secure, encrypted version.
Analogy: HTTP is like sending a postcard; anyone who intercepts it can read it. HTTPS is like sending a locked safe; only the recipient has the key.
Read more

S

Scalability
The property of a system to handle a growing amount of work by adding resources to the system.
Analogy: A restaurant being able to easily expand its kitchen and seating area when it gets more popular.
Read more
SOLID
Five design principles intended to make software designs more understandable, flexible, and maintainable.
Analogy: Best practices for building a house—like ensuring plumbing doesn't rely on the electrical system (Single Responsibility) and standardizing wall outlets (Liskov Substitution).
Read more
