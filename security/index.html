Security — Protecting Your System

1. Authentication vs Authorization
  • Authentication (AuthN): Who are you? (Verifying identity).
  • Authorization (AuthZ): What are you allowed to do? (Checking permissions).

Real-World Analogy: At an airport, showing your passport to security is Authentication. Your boarding pass dictating which specific plane you can board is Authorization.

2. Password Hashing

Never store plain text passwords! Always hash them using a strong algorithm like BCrypt, and add a salt (random data) to prevent rainbow table attacks.

import java.security.MessageDigest;
import java.security.SecureRandom;
import java.util.Base64;

public class PasswordHasher {
    public record HashedResult(String hash, String salt) {}

    public HashedResult hash(String password) throws Exception {
        byte[] salt = new byte[16];
        new SecureRandom().nextBytes(salt);
        
        MessageDigest md = MessageDigest.getInstance("SHA-256");
        md.update(salt);
        byte[] hashedPassword = md.digest(password.getBytes());
        
        return new HashedResult(
            Base64.getEncoder().encodeToString(hashedPassword),
            Base64.getEncoder().encodeToString(salt)
        );
    }
}

3. JWT (JSON Web Token)

A JWT is a stateless way to prove who you are. It consists of 3 parts: Header, Payload (claims), and Signature. The server verifies the signature to ensure the token wasn't tampered with.

sequenceDiagram Client->>Server: 1. Login (username, password) Server-->>Client: 2. Return JWT Client->>Server: 3. Request Profile (Header: Authorization: Bearer [JWT]) Server-->>Server: 4. Verify Signature Server-->>Client: 5. Return Profile Data

4. OAuth 2.0

An authorization framework that lets third-party apps access user data without giving them the password (e.g., "Login with Google").

sequenceDiagram App->>User: Request Permission User->>Google: Grants Permission Google-->>App: Authorization Code App->>Google: Exchange Code for Access Token Google-->>App: Access Token App->>Resource Server: Get User Profile (Access Token)

5. HTTPS / TLS

Encrypts data in transit. It uses Asymmetric encryption (public/private keys) to securely exchange a Symmetric key, which is then used to encrypt the actual data.

Real-World Analogy: Sending a locked box to a friend, but sending the key separately through a trusted courier.

6. CORS (Cross-Origin Resource Sharing)

Browsers block requests to different domains for security. Servers use CORS headers (e.g., Access-Control-Allow-Origin) to explicitly permit certain domains to make requests.

7. SQL Injection

Malicious users input SQL commands into your fields to manipulate your database. Always use Parameterized Queries or Prepared Statements.

BAD (Vulnerable) 
String query = "SELECT * FROM users WHERE name = '" + userInput + "'";
// If userInput is "' OR '1'='1", it fetches everyone!
GOOD (Secure) 
PreparedStatement stmt = conn.prepareStatement(
    "SELECT * FROM users WHERE name = ?");
stmt.setString(1, userInput);

8. XSS (Cross-Site Scripting) & 9. CSRF

  • XSS: Attackers inject malicious JavaScript into your site. Prevent by sanitizing user input and escaping outputs.
  • CSRF (Cross-Site Request Forgery): Tricking a logged-in user's browser to perform unwanted actions. Prevent using Anti-CSRF tokens.

10. API Security

Protecting your backend endpoints.

public class ApiSecurity {
    // Java 21 pattern matching in switch
    public boolean authorizeRequest(String role, String endpoint) {
        return switch (role) {
            case "ADMIN" -> true;
            case "USER" -> endpoint.startsWith("/api/public/");
            case null, default -> false;
        };
    }
}
public class ApiSecurity
{
    // C# 12 pattern matching switch expression
    public static bool AuthorizeRequest(string? role, string endpoint) => role switch
    {
        "ADMIN"                           => true,
        "USER" when endpoint.StartsWith("/api/public/", StringComparison.OrdinalIgnoreCase) => true,
        _                                 => false
    };
}

11. Principle of Least Privilege

Users and systems should only have the minimum permissions necessary to do their job.

12. Encryption at Rest vs In Transit

  • In Transit: Encrypting data over the network (HTTPS/TLS).
  • At Rest: Encrypting data stored on disks or databases (AES-256).
Interview Tip:
Always mention security in interviews. If asked to design a system, proactively say: "For security, we will use HTTPS for in-transit encryption, and encrypt PII (Personally Identifiable Information) at rest." It shows maturity.
