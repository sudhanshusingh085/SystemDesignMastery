Generics & Type System — Writing Flexible, Type-Safe Code

Leveraging Java's type system to build robust, reusable financial algorithms.

1. Why Generics?

Before Java 5, collections held Object. You had to cast elements, risking ClassCastException at runtime. Generics move type checking to compile time.

4. Bounded Types

Restrict the types that can be used as type arguments. Useful in financial calculations.

public static <T extends Comparable<T>> T maxPrice(T p1, T p2) {
    return p1.compareTo(p2) > 0 ? p1 : p2;
}

5. Wildcards and PECS

PILLAR 3: Step-by-Step Evolution & Thought Process

The PECS rule: Producer Extends, Consumer Super. If you need to read from a collection, use <? extends T>. If you need to write to a collection, use <? super T>.

// Read-only (Producer)
public void processTrades(List<? extends FinancialInstrument> instruments) {
    for (FinancialInstrument i : instruments) {
        // Can read as FinancialInstrument, but CANNOT add to list
    }
}

// Write-only (Consumer)
public void addTrade(List<? super Trade> dest) {
    dest.add(new EquityTrade());
    // Can add Trade and subtypes, but cannot read safely as a specific type
}

📋 How to Answer This in an Interview

Q: Explain wildcard bounds and the PECS principle.

A: <? extends T> sets an upper bound, meaning the collection contains T or its subclasses. It acts as a producer—safe to read T, but unsafe to add anything. <? super T> sets a lower bound, meaning the collection contains T or its superclasses. It acts as a consumer—safe to add T or its subclasses, but reading yields Object.

6. Type Erasure

Generics are a compile-time construct. At runtime, List<String> and List<Integer> are both just List. The JVM erases the type parameters and replaces them with their bounds (or Object).

🎯 Interviewer Follow-Up Questions

Q: Why can't you instantiate a generic type like new T()?

A: Because of Type Erasure. The JVM doesn't know what T is at runtime. To work around this, we pass a Class<T> token and use reflection, or use a Supplier/Factory pattern.

7. Generic Factory Pattern

public class InstrumentFactory {
    public <T extends Instrument> T create(Class<T> clazz) throws Exception {
        return clazz.getDeclaredConstructor().newInstance();
    }
}
