What is System Design?

Welcome to your journey into System Design! If you're new to software engineering, you might have heard this term thrown around a lot. But what does it actually mean? Let's break it down in simple terms.

What is a 'System'?

📖 System: A collection of separate parts that work together to accomplish a shared goal.

Think about a busy restaurant. A restaurant isn't just one thing—it's a system made of many moving parts:

  • The Menu: Tells customers what they can order.
  • The Waiter: Takes the order from the customer to the kitchen.
  • The Kitchen: Where the chefs prepare the food.
  • The Pantry: Where ingredients are stored until needed.

If any of these parts break down, the entire restaurant fails. In software, a system is very similar. It's not just "code running on a computer." It's multiple pieces of software (servers, databases, networks) cooperating to serve users.

What is 'Design'?

Before building a skyscraper, engineers don't just show up with concrete and start pouring. They create detailed blueprints. They plan the foundation, the plumbing, and the electrical grids. This planning phase is Design.

In software, jumping straight into coding without a plan usually leads to messy, unscalable applications. Design is the process of deciding how things should be built before writing a single line of code.

Analogy: Design is like planning the layout of our restaurant. How many tables can fit? Where should the kitchen be? Do we need a separate pickup window for takeout?

What is 'System Design'?

Putting it all together, System Design is the process of defining the architecture, components, modules, interfaces, and data for a system to satisfy specified requirements.

It's planning how all the different parts of a software application—the user interface, the servers, the databases, the background jobs—will communicate and work together to deliver a reliable, fast, and scalable product to the end user.

Why do companies care?

Why is system design so important, especially at large tech companies? It comes down to three main factors:

  • Scaling: If your restaurant suddenly gets 10,000 customers in one day, your single chef will be overwhelmed. System design helps you figure out how to add more "chefs" (servers) to handle the load seamlessly.
  • Reliability: What happens if a server crashes? A good design ensures the system stays online even if individual components fail.
  • Cost: Running servers costs money. Efficient design minimizes wasted resources, saving millions of dollars at scale.

High-Level Design (HLD) vs Low-Level Design (LLD)

System design is often split into two categories:

High-Level Design (HLD)

Like City Planning. You decide where the residential zones, commercial zones, and highways go. You don't care about the layout of individual houses.

In software: Deciding what databases to use, how load balancers route traffic, and the overall architecture (e.g., Microservices vs Monolith).

Low-Level Design (LLD)

Like a House Blueprint. You plan exactly where every wall, door, and electrical outlet will be placed in a specific house.

In software: Deciding which classes, interfaces, and design patterns to use in your Java code. Creating database schemas and API definitions.

What does a system designer actually do?

A software engineer designing a system will usually perform the following steps:

1
Understand Requirements: Clarify exactly what the system needs to do. (e.g., "Users should be able to upload photos and view a feed.")
2
Estimate Capacity: Calculate how much traffic and data the system will handle. (e.g., "We expect 1 million uploads a day.")
3
Define APIs: Plan how different components will talk to each other.
4
Draw the Architecture: Create diagrams showing servers, databases, and caches.

Code Implementation: Modeling a Request and Response

Even at a high level, components communicate via requests and responses. We can model this elegantly using immutable records and switch pattern matching in modern Java 21 and C# 12.

/**
 * Using Java 21 Records to model a simple API Request and Response.
 * Records are immutable data carriers, perfect for transferring data
 * between different parts of a system.
 */
public class SystemDesignBasics {

    // A request sent by a client (e.g., a user's web browser)
    public record ApiRequest(String endpoint, String payload) {}

    // A response returned by the server
    public record ApiResponse(int statusCode, String body) {}

    // A simple mock server handler
    public static class SimpleServer {
        public ApiResponse handleRequest(ApiRequest request) {
            System.out.println("Processing request to: " + request.endpoint());
            
            // Using Java 21 Enhanced Switch
            return switch (request.endpoint()) {
                case "/home" -> new ApiResponse(200, "Welcome Home!");
                case "/about" -> new ApiResponse(200, "About Us");
                default -> new ApiResponse(404, "Page Not Found");
            };
        }
    }

    public static void main(String[] args) {
        SimpleServer server = new SimpleServer();
        
        ApiRequest req1 = new ApiRequest("/home", "");
        ApiResponse res1 = server.handleRequest(req1);
        System.out.println("Response: " + res1); // Prints 200, Welcome Home!
    }
}
using System;

// Using C# 12 Positional Records to model immutable API Request & Response
public record ApiRequest(string Endpoint, string Payload);
public record ApiResponse(int StatusCode, string Body);

public class SimpleServer
{
    public ApiResponse HandleRequest(ApiRequest request)
    {
        Console.WriteLine($"Processing request to: {request.Endpoint}");
        
        // C# 12 Pattern Matching switch expression
        return request.Endpoint switch
        {
            "/home"  => new ApiResponse(200, "Welcome Home!"),
            "/about" => new ApiResponse(200, "About Us"),
            _        => new ApiResponse(404, "Page Not Found")
        };
    }
}

public static class Program
{
    public static void Main()
    {
        var server = new SimpleServer();
        
        var req1 = new ApiRequest("/home", "");
        var res1 = server.HandleRequest(req1);
        Console.WriteLine($"Response: {res1}"); // Prints 200, Welcome Home!
    }
}
Interview Tip: System Design is the #1 interview topic for senior roles because it tests your experience. You can memorize algorithms, but designing a system requires you to weigh trade-offs (e.g., speed vs accuracy, consistency vs availability). Always be prepared to explain why you chose a specific design.
