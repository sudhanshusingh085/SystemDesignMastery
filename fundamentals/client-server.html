Client & Server Architecture

Every time you use the internet, whether to watch a video, send a message, or read this very article, you are participating in the Client-Server model. It is the fundamental building block of web architecture.

What is a Client?

📖 Client: A device or software application that requests data or services from another system.

Your smartphone, your laptop, your web browser (like Chrome or Safari), and even smart TVs are clients. They don't generate the data themselves; they ask for it. The client is the thing you interact with directly.

What is a Server?

📖 Server: A powerful computer running specialized software that waits for requests from clients and sends back the appropriate data.

A server is essentially a computer that is always turned on, connected to a fast internet connection, and programmed to serve. When you ask to see a web page, the server is the machine that finds that page and sends it back to you.

Real-World Analogy: The Restaurant
Imagine you are at a restaurant.
• You (The Client): You sit at the table and look at the menu. You request food.
• The Kitchen (The Server): The kitchen receives your order, prepares the food, and sends it back. It responds to your request.
• The Waiter (The Network): The waiter carries your request to the kitchen and brings the food back to you.

How do they talk? Request & Response

Communication between a client and a server happens in a strict two-step dance:

  1. Request: The client asks the server for something.
  2. Response: The server answers the client, either providing the data or explaining why it couldn't (like an error message).

What is HTTP?

If a client speaks English and a server speaks French, they can't communicate. They need a common language. On the web, that common language is HTTP.

📖 HTTP (HyperText Transfer Protocol): The set of rules that defines how messages are formatted and transmitted across the web.

When you type `http://` or `https://` in your browser, you are telling the browser to use this specific language to talk to the server.

What is an API?

A server might be capable of thousands of different things. How does the client know what to ask for? It uses an API.

📖 API (Application Programming Interface): A set of defined rules that allows one piece of software to communicate with another. It acts like a menu in a restaurant, listing all the available operations.

What happens when you type google.com?

This is a classic interview question! Let's break it down simply:

1
You type `google.com` (Client action).
2
Your computer finds the IP Address of Google's servers.
3
Your browser sends an HTTP Request to that IP Address.
4
Google's Server receives the request, builds the search page HTML.
5
The Server sends an HTTP Response containing the HTML back to your browser.
6
Your browser renders the HTML onto your screen.

Java 21 Code: A Simple Client-Server Program

Java includes built-in tools to create HTTP servers and clients. Here is a simple example using the modern Java HTTP Client and the lightweight HttpServer.

Java 
import com.sun.net.httpserver.HttpServer;
import java.io.IOException;
import java.io.OutputStream;
import java.net.InetSocketAddress;
import java.net.URI;
import java.net.http.HttpClient;
import java.net.http.HttpRequest;
import java.net.http.HttpResponse;

/**
 * Demonstrates a basic Client-Server interaction in Java.
 */
public class ClientServerExample {

    // 1. Define the Server
    public static void startServer() throws IOException {
        // Create a server listening on port 8080
        HttpServer server = HttpServer.create(new InetSocketAddress(8080), 0);
        
        // Define an API endpoint (context) at "/hello"
        server.createContext("/hello", exchange -> {
            String responseMessage = "Hello from the Java 21 Server!";
            
            // Send HTTP 200 OK status and the length of the message
            exchange.sendResponseHeaders(200, responseMessage.getBytes().length);
            
            // Write the response body
            try (OutputStream os = exchange.getResponseBody()) {
                os.write(responseMessage.getBytes());
            }
        });
        
        // Start the server in the background
        server.setExecutor(null); 
        server.start();
        System.out.println("Server started on port 8080...");
    }

    // 2. Define the Client
    public static void makeClientRequest() throws Exception {
        // Create a modern Java HttpClient
        try (HttpClient client = HttpClient.newHttpClient()) {
            
            // Build the HTTP Request
            HttpRequest request = HttpRequest.newBuilder()
                    .uri(URI.create("http://localhost:8080/hello"))
                    .GET()
                    .build();

            // Send the request and get the response
            System.out.println("Client sending request to /hello...");
            HttpResponse response = client.send(request, HttpResponse.BodyHandlers.ofString());

            // Print the result
            System.out.println("Client received Status Code: " + response.statusCode());
            System.out.println("Client received Body: " + response.body());
        }
    }

    public static void main(String[] args) throws Exception {
        startServer();
        
        // Wait a tiny bit to ensure server is up
        Thread.sleep(500); 
        
        makeClientRequest();
        
        System.exit(0);
    }
}
Important: In the real world, servers handle thousands of concurrent requests, meaning they need robust multithreading. Modern Java handles this beautifully with Virtual Threads, introduced in Java 21, which allow millions of lightweight threads to run simultaneously.
